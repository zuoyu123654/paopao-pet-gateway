## 0. 一句话结论

桌宠是 PyInstaller 打包的闭源程序，**没法给它加本地 TTS 后端**（内置只有 edge / MiMo / SAPI / 豆包，

```
桌宠 ──(OpenAI 兼容, base_url=http://127.0.0.1:9888)──> 网关 ──> https://api.deepseek.com

                                                        ├─> DSH 事件(dsh-pet-bridge/*.jsonl) ──> 状态播报
                                                        └─> 生活桥 /pet/inbox ──> 记忆(private_pair)
桌宠原生语音全部关掉，否则两套声音叠。
```

## 4. 网关 v2 做了什么

### 4.1 朗读范围

| 来源 | 怎么读到 | 念不念 |
|---|---|---|
| 聊天回复 | 经过网关（provider） | ✅ 流式接、按标点切句 |
| 框选识屏 / 主动识屏的回答 | 经过网关（vision 请求） | ✅ 直接念答案（**2026-11-17 起不先念「让我看看」**） |
| 识屏预提示（「让我看看」） | 网关看到 vision 请求就先念一句 | ❌ 已关：`tts.pre_cue` 默认空，桌宠 `proactive_screen.pre_cue=false` |
| DSH 开工 / 收工 / 报错 / 要你拍板 | 盯 `%APPDATA%\dsh-pet-bridge\dsh-*.jsonl` | ✅ |
| DSH **跑工具**（读了什么文件、跑了什么命令） | 同上 | ❌ 已关（`dsh.speak_tools=false`），太吵 |
| 点击自言自语、语音报时、节日/待办/抽签 | 本地事件，不经过 provider | ❌ 读不到 |

> DSH 状态是网关按同样的事件流**自己重念**，措辞来自内置模板，可能和气泡里那句不完全逐字。

### 4.2 提速 + 打断

1. 上游 `stream=true`，边生成边收；
2. 攒到 `。！？；…~` 就切一句，**立刻**丢进合成队列；
3. 2 个合成线程并行，播放线程按顺序播——第一句在播时，后面已经在合成；
4. **新的打断旧的**：高优先级（新回复 / 新状态）立刻 `PlaySound(None)` 掐掉正在播的那句、丢掉队列里没播的、删临时音频，改念新的；
5. **分级**：`chat/vision/say/mode` = 10，`precue` = 6，`dsh` = 2。
   低优先级（DSH 状态）**不打断**正在说的正事，也**不会被丢**：先记到 `deferred`，
   等当前回合 + 队列 + 正在响的音频都结束，再补念（同类 DSH 只留最新一条）。

实测：整段回复 1.6s 收完；首句音频 2–3s 出来；`/say` 连发两句时第二句确实顶掉第一句。

**2026-11-17 起：「让我看看」默认去掉（老大嫌会话/进模式时冒出来）。**

- 网关 `tts.pre_cue` 默认 `[]`，`arm_vision_cue()` 直接返回，不再念提示音；
- 桌宠自己的 `proactive_screen.pre_cue` 设成 `false`，不再冒「让我看看」气泡；
- 启动时 `warm_pre_cues()` 也不会再合成；老缓存文件留在 `audio/precue/` 不播，可不管。

旧设计（2026-11-15）是识屏前先念一句、预缓存；现在已按老大要求关掉。

### 4.3 音量与语速

- `tts.volume` = **1.0（默认，不放大）**：合成后用 `audioop.mul` 对 PCM 加增益再播；1.0 就是原样，
  大于 1 是放大（超过 2.5 会削波）。2026-11-17 老大说「有的太大声了」，从 1.2 退回 1.0；
  想再响一点再调，**别一上来就 1.5 以上**。
- `tts.speed` = **1.2**：直接传给 GPT-SoVITS 的 `speed_factor`，用它自己的时长缩放，
  不是我们重采样，所以不会顺带把音高顶上去。
  实测同一句：1.0 → 9.74s，1.2 → 8.06s，1.3 → 7.52s。嫌慢改 1.3，嫌快退 1.1。


### 4.4 识屏账本 + 定时摘要（2026-11-15 加）

账本 ledger.jsonl 里原始记录一条不删；但**注入只有两样东西**：

1. **近况**：最近 inject_recent_minutes（默认 45 分钟）内最多 inject_recent_entries（默认 3）条原文，
   同一进程只留最新一条（十个浏览器标签不会占满额度）；
2. **更早的摘要**：digest.json，一段 ≤ max_chars（默认 240 字）的概括。

摘要由一个后台线程（Digester）每 interval_hours（默认 3 小时）做一次：
把「上次摘要之后、且不在最近 45 分钟内」的记录交给模型压成两三句
（「老大主要在用什么、在做什么、你当时怎么反应」），不够 min_entries（默认 8 条）就跳过，省 token。
网关启动时会先跑一次。

手动触发：curl -X POST http://127.0.0.1:9888/digest

实测（20 条 → 122 字）：

> 老大这段时间主要在星穹铁道里下棋、打游戏，也切到浏览器刷视频和AI相关内容，
> 还反复捣鼓 DeepSeek Harness 小助手，调参数、改代码、折腾记忆互通……

再问「我今天在忙什么？」她就照这个答得上来，而注入量只有一两行原文加一段摘要。

配置（config.json）：

| 键 | 默认 | 说明 |
|---|---|---|
| inject_recent_minutes | 45 | 近况窗口；越小越省，太大就又开始塞原文 |
| inject_recent_entries | 3 | 近况最多几条 |
| ledger_digest.enabled | true | 关掉就退回「只注入最近几条原文」 |
| ledger_digest.interval_hours | 3 | 多久摘一次 |
| ledger_digest.min_entries | 8 | 少于这么多条就先不摘 |
| ledger_digest.max_chars | 240 | 摘要上限 |

### 4.4b 识屏之间的连续性（2026-11-15 加）

原来每次识屏都是「独立事件」：请求里只有当前这张图 + 前台程序名，她不知道两分钟前刚看过什么，
所以说出来的话像第一次看见。

现在**识屏请求也会带上近况**：build_vision_context() 取最近 vision_context_minutes（默认 20 分钟）
内最多 vision_context_entries（默认 2）条她自己说过的话 + 当时的前台程序，作为一段 system 注入，
并明确写「现在这张是此刻，只有接得上时才提变化，不要复述」。

实测：先造一条「在星穹铁道下棋」的记录，再发一张 B 站截图，她回
「老大又从星穹铁道跑回 B 站啦～这回是想找点什么呢」——接上了。

配置：`inject_vision_context`（默认 true）、`vision_context_entries`、`vision_context_minutes`。

**2026-11-15 追加：同 App 优先 + 按字符预算装。**
不再按「条数」装，而是按**字符预算**（默认 600 字）：先用当前前台程序的记录填满，
装不下才用别的窗口补；每条截到 90 字。看番时就不会被游戏/编辑器的记录挤掉。
参数：`vision_context_minutes`（180）、`vision_context_budget_chars`（600）、
`vision_context_item_chars`（90）、`vision_context_entries`（6，条数上限）。

**2026-11-16：加「时间感」（她识屏本来就是 2 分钟以上一次，光说「刚才」会穿帮）。**

- 每条记录都标 `21:41（3分钟前）`，**但提示词写死：这些数字是给她判断的，不许念出来**；
- 说话时只能用自然词：10 分钟以内「刚才/刚刚」；10～30 分钟「刚才那会儿」「前一会儿」；
  半小时以上只能说「之前」「早先」，而且**只有跟眼下明显相关才提**；更久就说「下午那会儿」「今天早些时候」；
- 更自然的做法是**用内容指代**（「你不是一直在看那部片子吗」「你 B 站刷的那个视频」），
  比任何时间词都准；
- 旧内容只是**参考**，不是必须提——眼下这张图够答就只说这张图；
- 窗口从 30 分钟放宽到 **180 分钟**（看电影两个小时也接得上），超出预算的旧记录由摘要压缩后注入
  （`build_ledger_block` 里的「更早之前…」那段）。

### 4.4c 识屏带「前几秒」（帧缓冲，2026-11-15 加）

桌宠每次识屏只发一张当下的截图，所以她只会说「此刻」。为了让她说得出「你刚才还在干什么」，
网关自己维护一个**只存在内存里的帧缓冲**：

- 每 `interval_seconds`（默认 1 秒）截一张全屏，缩到 `frame_width`（默认 640）后放进 deque，
  只留 `keep`（默认 5）张，**不落盘**；
- 收到识屏请求时，取前 `grid_frames`（默认 4）张按时间拼成 2×2（左上 → 右下），
  以 data URL 形式**插在桌宠那张当前截图之前**，并附一句说明「刚才 4 秒每秒一张；
  紧接着那张才是此刻」；
- 第 5 张就是桌宠自己抓的、全分辨率的当前帧，所以最新画面不会被压糊。

**为什么不是「送两次」**：两张图放在**同一个请求**里，模型能一次性对比「刚才 vs 此刻」，
只回一句话、只念一遍、只花一次调用；拆成两次请求会得到两段回复、念两遍，还多一次调用。

实测：`POST /frames` 返回 4 帧、1280×720 / 160KB（`logs/last_grid.jpg`），四格里字还读得清。

配置（`frame_buffer`）：`enabled` / `interval_seconds` / `keep` / `frame_width` /
`jpeg_quality` / `grid_frames` / `attach_to_vision`。
关掉就把 enabled 设 false，注入只剩文字近况（4.4b）。

### 4.4d 压掉「那个不就是我吗」（2026-11-15 加）

根因不在她，在**桌宠自己塞进识屏请求里的那句身份提示**（原文）：

> （身份提示：画面边缘或角落里如果有一个动漫风格的桌面宠物形象，那就是你自己「泡泡」——
> 你在老大桌面上的化身。请以第一人称自然看待它（比如「我在你桌面上呢」）……）

她是桌面宠物，**桌面上永远有她自己**，这句等于每次都提醒她去认领，于是几乎每张截图都要说一次。

网关侧三条刹车（都不改桌宠代码）：

1. **改写那句提示**：换成「可以说，但别老说；只有老大问你、或者你正好在做事时才顺口一句；
   同一个梗隔很久才用一次」；
2. **不回喂旧话**：build_vision_context 里，把她以前那几句「那不就是我」剥掉再注入，
   否则她会照着自己复读；
3. **冷却**：`self_recognition.cooldown_minutes`（默认 90）内说过一次，这一轮直接加一句
   「刚刚已经说过，这轮别再提自己」。

实测：给同样的身份提示 + 上一条刚说过「角落里那个不就是本鲸鱼娘嘛」→
日志出「识屏：压一下自我认领（刚说过）」，她的回复完全没提自己，只说老大在玩星穹铁道。

配置：`soften_self_recognition`（开关）、`self_recognition.cooldown_minutes` /
lookback_minutes。想更狠把 cooldown 调大（240），想几乎不出现就 1440。

### 4.2b 首句流式播放（2026-11-15 加，针对「去掉让我看看之后显得慢」）

> ⚠ 2026-11-16 定稿改成：**只有第一小句走流式，后面的句子回到整句合成**（见 4.2e）。
> 下面这一段是当时「全走流式」的设计和实测量，留着做参照；配置键名没变。

问题：以前是「整句合成完 → 播」，一句长的要 3～4 秒才出声；去掉「让我看看」的提示音后，
那几秒就是纯静默，体感就是“变慢了”。

做法：GPT-SoVITS 的 `api_v2` 支持 `streaming_mode`（0/1 关，2/3 开）。
开的时候回包是「一个 wav 头 + 连续 PCM」，所以我们不等整句合成完：

1. 第一句走流式：读到 44 字节 wav 头拿到采样率（32000Hz/单声道），后面的 PCM
   直接喂给 `sounddevice.RawOutputStream`，边到边播；
2. 其余句子仍由两个合成线程**提前**合成成文件，第一句播完接上（不出现空档）；
3. 打断逻辑同时管两条：流式的那条 `stream.stop()`，文件那条 `PlaySound(None)`。

实测（同一句话）：

| 方式 | 首字节 | 整段完成 |
|---|---|---|
| 普通（streaming_mode=0） | 4.17s | 4.17s |
| 流式（=3） | **0.25s** | 3.7s |
| 流式（=2，质量更好） | 0.46s | 2.5s |

网关日志里能看到每次的 `流式开播：32000Hz 1ch（首字节 0.25s）`。
从 `念(say)` 到真正出声，稳定在 **0.25～0.28 秒**。

配置：`tts.streaming_first`（默认 true，关掉就退回整句合成）、
`tts.streaming_mode`（默认 3 最快；2 是中等质量）。

依赖：`sounddevice`（已装进网关的 Python 环境）。
音量仍按 `tts.volume`（默认 1.0，不放大）在 PCM 上乘，超出部分 clip，避免爆音。

### 4.2c 语音断在半句 / 同一句念两遍（2026-11-15 晚修）

**症状**：偶尔「第一句念到一半就没了，后面几句也没声」，接着又听她把**同一句从头念一遍**。

**根因不在网关，在 GPT-SoVITS 自己**：`api_v2` 是单进程多线程，所有请求共用同一个模型对象，
而 `TTS.py` 的 `run()` 会按本次请求把方法**写回共享属性**：

```python
self.t2s_model.model.infer_panel = self.t2s_model.model.infer_panel_naive      # 流式
self.t2s_model.model.infer_panel = self.t2s_model.model.infer_panel_batch_infer # 非流式
```

我们的流水线天生是并发的：第一句流式播，第二/三句同时用非流式合成。只要非流式请求在
「流式请求绑好方法、还没走到调用」这几百毫秒里插进来，流式请求拿到的就是普通函数，
`for semantic_tokens, is_final in ...` 一迭代就崩：

```
TTS.py, line 1397, in run
ValueError: not enough values to unpack (expected 2, got 1)
```

服务端异常 → HTTP 连接中途断开 → 网关读到 `IncompleteRead` → 退回普通合成把整句重念。

**修法（服务端，根治）**：`TTS.py` 里不再写回共享属性，改成每次 `run()` 用局部变量
`infer_panel_fn`，两个调用点都用它。备份在
`GPT_SoVITS/TTS_infer_pack/TTS.py.bak-racesafe-20261115`。
⚠ **升级 GPT-SoVITS 会覆盖这个补丁**，升级后要按上面两条改回去。

**修法（网关侧，兜底）**：

- 非流式合成失败自动重试 3 次（0.4s/0.8s 退避），不再「一次失败就丢整句」；
- 流式播放返回状态：连不上（failed）→ 退回普通合成补播；**已经播出去 ≥0.5 秒才断**
  → 只记日志、**不重念**（重念就是听见同一句说两遍）；断在 0.5 秒内才补；
- 回包不是 `RIFF` 头就当失败（不然会把错误 JSON 当 PCM 播出杂音）。

**验证**：并发压测（1 流式 + 1～2 非流式同时打 9882）
修复前 8～10 轮里必挂 1 次；修复后 **60 次并发 0 失败**，流式首字节 0.49s、三句全播完。

### 4.2d 原文到出声的时间账（2026-11-15 晚测）

同一句话连问三次，网关日志里现在有完整时间戳（`首字` / `首句入队` / `流式开播`）：

| 场景 | 首字 | 首句入队 | 开口（首字节） | 从请求到听见 |
|---|---|---|---|---|
| chat（对话） | 1.6–2.1s | +0.1–0.2s | +0.47–0.52s | **≈2.1–2.6s** |
| vision（识屏） | 1.9–8.7s | +0.1–0.2s | +0.47–0.52s | **≈2.4–9.2s** |

结论：**TTS 不是瓶颈**——拿到首句到开口稳定在 0.5 秒内；
识屏慢在「模型看画面」那一段，2～9 秒波动来自 DeepSeek 视觉侧，不是本机算力。

为此改了四处（2026-11-15 深夜定稿）：

1. **首句一律走流式**（不再看 20 字门槛）。以前短句会退回整句合成，
   整句要 1～2 秒——这就是老大说的「字都出来了，声音还要等一两秒」。
   流式首字节 0.5 秒，短句也是。
2. **第一句按「短句」切**（2026-11-15 深夜最终版）：逗号、分号也算断点，
   凑够 **8 个字（大于 7）** 就切走当第一句，剩下的按正常句号切。
   （2026-11-16 晚：门槛仍是 8 字；改成把**第二段也按标点切短**来补，见 4.2e。）
   `take_first_sentence()` 干这件事。这样第一句最短也是「哎，老大你在看呢，」
   这种长度，不会单独蹦一个「哎」。
   配套：省略号/波浪号前面不足 6 字不算句末；整句切分时不足 4 字的碎片并到后一句。
3. **首句优先**：第一句入队后，后面几句合成前先等「首句已开口」（最多 1 秒）。
   以前三路同时抢 GPU，首字节从 0.5s 拖到 3.8s。
4. **提示音不再推迟**（回退）：试过按估算推迟到首句前，结果提示音和正片抢音频
   设备，整体反而更慢。现在请求一到就播，只保留「首句已开口就不播」的保护。
   **只给「让我看看」剪静音**：预存提示音尾巴原来有 0.33s / 0.50s 空白，剪到 0.12s；
   新合成的正文**不剪**（剪了听着发紧、发怪，老大叫停）。
5. **流式播放改成「读一个线程、写一个线程」+ 0.6 秒垫底**（2026-11-15 深夜，修「念个哎就卡住」）：
   GPT-SoVITS 的流是**一阵一阵**吐的——实测第一阵只有 0.45 秒（差不多就是「哎，老大」），
   第二阵要再等 0.4 秒。原来读一块写一块，声卡 0.1 秒缓冲一空就断粮，听起来就是
   「哎」→ 卡一下 → 再往下念。现在读到队列、另一个线程按声卡节奏写，并且攒够
   `tts.prebuffer_seconds`（默认 0.6s）再开声；同时**文件合成串行**（`synth_lock`），
   避免流式 + 两个文件一起抢 GPU 把流拖到比实时还慢（实测 1 文件 RTF 0.62，2 文件 1.34）。
   代价：开口从 0.5s 变成约 1.1s，但不再卡。

   **「卡在『哎』后面」的真正原因（2026-11-15 深夜定案）**：不是网络断粮，也不是声卡，
   是**音频里本来就有一段静音**。GPT-SoVITS 按 `text_split_method=cut5` 在逗号处把
   文本切成两段分别生成，第一段「哎，」尾巴带一截很长的空白。把生成的 wav 拆开量
   早期最长静音（3 次取样本）：

   | 送进去的文本 | 早期最长静音 |
   |---|---|
   | 带标点 + cut5（旧行为） | 0.42 / 0.60 / 0.43 秒 |
   | 去标点 + cut5 | 0.20 / 0.26 / 0.14 秒 |
   | 去标点 + cut0（不切） | 0.16 / 0.18 / 0.22 秒 |

   所以流式这条改成：**送 TTS 前去掉标点 + `text_split_method=cut0`**
   （`tts.strip_stream_punct=true`、`tts.stream_split_method=cut0`）。
   注意：之前只看网络回包节奏会误判「标点无关」——网络分块确实与标点无关，
   但音频内容里的静音是切段造成的。

6. **再剪一道「内部长静音」**（2026-11-15 深夜，治「一卡一卡」）：
   去标点后仍有 0.4～0.7 秒的句中静音（模型自己的换气/分段），听感就是
   「说两三个词停一下」。`shorten_pauses()` 把**句中**超过 `tts.max_internal_pause`
   （默认 0.28 秒）的静音压到 0.28 秒，有声部分一个采样都不动；流式实时做
   （跨块记状态），整句合成在写盘后做。实测同一句：总长 6.69s → 6.20s，
   最长句内停顿 0.67s → 0.28s。**头尾不剪**（那是老大嫌怪的那种，已撤）。

现状：文字出现到听见 ≈ **0.3～0.5 秒**；从发起到听见还是 2～9 秒，
取决于模型那一次快不快。

`/status` 新增 `first_byte_ms`（首字节 EWMA）和 `synth_ms`（整句合成 EWMA），随时能看。

### 4.2e 第一小句流式、后面整句合成（2026-11-16 定稿，取代 4.2d 的「全走流式」）

**背景**：11-16 凌晨试过「整段回复逐句流式」（全部 `streaming_mode=3` + 预取），
句子之间能接到 0.01 秒，但老大听完说**流式出来的音质明显差一截**（固定长度分块
加 SOLA 拼接的接缝味），要退回整句合成。最后定的是折中：

| 位置 | 走哪条 | 关键参数 |
|---|---|---|
| 前 3 段（逗号/分号/顿号/冒号都算断点，够 8 字） | 第一段流式、后两段整句合成 | `early_sentences=3`、`early_min_chars=8`、第一段流式参数见 4.2d |
| 其余句子 | 整句合成（`cut5`，非流式） | 语速 1.2、一句 32 字 |

**为什么第一小句语速要 1.0**：同一句话实测，1.2 时这一小句 2.48 秒，1.0 时 2.78 秒；
更要紧的是末尾「已经生成好、还压在缓冲区」那截从约 1.1 秒涨到 1.4 秒——等于给下一段
的合成多拖出半秒。老大听感上没有明显的「先慢后快」。

**句子长度取 32 字**（`max_chars_per_sentence`，原来是 60，中途试过 24）：
- 60 字：一段要合成 5.5 秒以上，第一小句说完还得好几秒才接得上；
- 24 字：接是接得快，但切得太碎，碰上一小段就没声音了，反而每段之间都听得出停顿；
- **32 字**：一段合成 4～5 秒、念 6 秒左右，正好接住，停顿最少。别低于 24。

**前 3 段都按标点切短**（`early_sentences=3`、`early_min_chars=8`，2026-11-16 再定）：
之前只有第一段、第二段按标点切，第三段起走「整句 32 字」，老大听着第三段又变慢了
（第一段只念 2～3 秒，第二段那点字数盖不住第三段 4～5 秒的合成）。现在**前 3 段统一**
按标点切、够 8 个字就走（逗号、分号、顿号、冒号、省略号都算），第 4 段起恢复正常。
实测一条 116 字的回复被切成 4 段，前两段分别 11/8 字，开口时间 2.18 秒。

> 代价要知道：这是「每段念的时间和下一段合成的时间互相盖住」的账。
> 碰上一整段只有 5～7 个字（它念 1 秒、下一段要合成 3 秒），照样会冒 1～2 秒的洞，
> 只是不会像以前那样每段都断。每多送一次合成还有约 1.2 秒固定开销（模型前置 + 解码），
> 所以「切得更碎」不是越碎越好。

**实测（98～143 字的回复，2026-11-16 晚）**：
- 开口（从送进 TTS 算）0.85～1.1 秒；从发起到听见约 2.0～2.5 秒（大头是模型出字）；
- 第一小句 2.4～4.8 秒音频（看它第一个逗号落在哪）；第二、三段（按标点切的五到十个字）
  **在它说话时就合成好**，第一口实测 0～0.1 秒；

### 4.2f 补丁：整句合成别把事件循环堵死（2026-11-16，治「第二句要等 5 秒」）

**症状**：第一小句正常，接第二段时空 5 秒左右。日志里是
`整句合成好：36 字，用了 5.57s`，而这 5 秒里流式那边一个字节都发不出去。

**根因**（很反直觉）：`api_v2.py` 的 `/tts` 非流式分支是

```python
else:
    sr, audio_data = next(tts_generator)   # ← async 函数里同步跑 3～6 秒
```

`tts_handle` 是 `async def`，这一行把 **uvicorn 的事件循环整个占住**，同一个服务上
正在推流的那条 `StreamingResponse` 也就没法往外写。所以加独占锁、换 CUDA 流都治不好，
必须先把「堵事件循环」这个点搬走。

**修法（`api_v2.py`，两处）**：

1. 整句合成挪进线程池：
   ```python
   from starlette.concurrency import run_in_threadpool
   ...
   sr, audio_data = await run_in_threadpool(_synth_blocking)
   ```
2. 线程里再给它一条独立的 CUDA 流（同进程默认都在 stream 0 上排队）：
   ```python
   def _synth_blocking():
       _s = _pick_cuda_stream()
       if _s is None:
           return next(tts_generator)
       import torch
       with torch.cuda.stream(_s):
           out = next(tts_generator)
       _s.synchronize()
       return out
   ```
   `_pick_cuda_stream()` 是个 4 条流的轮转池，第一次用时先 `torch.cuda.synchronize()`
   对齐模型权重。

**实测（1 条流式 + 1 条整句同时打 9882）**：

| 情况 | 流式速度 | 流式最长空档 |
|---|---|---|
| 只跑流式（对照） | 1.19x | 0.49s |
| 补丁前，同时跑一条整句 | 0.68x | **5.4s** |
| 补丁后，同时跑一条整句 | 1.06x | **0.88s** |

补丁后流式基本贴着实时跑，网关这边才敢放开并发（`exclusive_gpu=false`）：
第一小句一边说，下一条一边合成。

**备份 / 回滚**：改前是 `api_v2.py.bak-cudastream-20261116`（同目录），覆盖回去、重启
9882 就还原。⚠ **升级 GPT-SoVITS 会覆盖这个补丁**，和 4.2c 那个 `TTS.py` 补丁一样，
升级后要重打。

**验证**：两条请求同时打，流式那边的空档不能超过 2 秒。用
`D:\app1\AstrBot\venv\Scripts\python.exe` 跑：一条 `streaming_mode=3&min_chunk_length=16`，

### 4.2g 「干完活」一次念两遍（2026-11-16 修）

### 4.2h 「后面几句卡」和「句与句之间能听出空档」（2026-11-17 修）

**症状**（老大原话）：「识屏语音念出来，中间还是能感到明显间隔」「老是后面几句会卡」。

**先量，别猜**。两处硬指标：

1. **合成出来的每一句两头都有静音**：抽 12 个句子 wav 量，句首静音 0.06～0.19 秒、
   **句尾静音 0.35～0.56 秒**。句尾 + 下一句句首 ≈ 0.5～0.7 秒，每接一句就空半秒多，
   听起来就是「一句一句往外蹦」——这是「明显间隔」的主因，跟卡不卡无关。
2. **整句合成一条一条排队，追不上播放**：一条 18～25 字的句子合成要 3.5～6 秒，
   播出来只有 3.5～4.5 秒（语速 1.2）；旧代码 `synth_lock` 全局只许 1 条并行，
   于是越往后越落后。翻 11-16～11-17 的识屏日志，句间真空白 1.4、1.9、2.1、3.6 秒都出现过。

**三处修改（都在 `gateway.py`）**：

1. **句子两头静音掐紧**（`tight_sentence_edges`）：播之前把每句 wav 的句首剪到
   `sentence_head_pad=0.03` 秒、句尾剪到 `sentence_tail_pad=0.08` 秒，
   **句中一个采样都不动**（`max_internal_pause` 仍然是 0，别混了——那个是剪句中，
   老大嫌难听，早撤了）。句间静音从 0.5～0.7 秒降到 0.11 秒左右，且对缓存文件幂等。
2. **整句合成并发**（`synth_parallel=2`）：实测同一条句子，2 条并发每条的耗时只多
   约 10%，一批 4 句的总时间从 18 秒降到 9.5 秒（吞吐 1.5 倍），合成速度这才压过播放。
   但**首句还在流式吐音频时只许 1 条陪跑**（`_synth_slot()` 按「第几代」判：`stream_done_gen`），
   三条一起挤 GPU 时流式会掉到实时以下、第一句变成「念两个词停一下」——
   实测无限制 2 条并行时第一小句要多卡 0.66～1.0 秒，加了这道闸门回到 +0.02～0.21 秒。
3. **第一段至少 24 字**（`first_min_chars`，原来是 8）：第一段只有 8～9 字时音频才
   1.6～2.4 秒，而第二句合成要 3.5～4.5 秒——无论怎么并发，第一段念完第二句都没好，
   那个空档躲不掉。24 字左右时第一段有 5.5～8.4 秒音频，正好把第二句的合成盖住。
   （`early_min_chars=8` 管的是第 2、3 段，不变。）

**改完实测（2026-11-17 01:06～01:11，连续三轮真识屏）**：

| 指标 | 改前 | 改后 |
|---|---|---|
| 句子之间的静音（音量表上量的） | 0.5～0.7 秒 | 0.11 秒 |
| 后面第 2～4 句前等合成的空洞 | 1.4～3.6 秒 | **0.00 秒**（三轮都是） |
| 第一小句自己有没有被打断 | +0.04～0.16 秒 | +0.02～0.21 秒（没变差） |

**怎么看是不是又犯了**（日志关键词）：

```text
念第16句：3.02s 音频（跟上一句隔着 0.00s）   ← 0.00 就是接上了；>0.35 会另起一行
句间空档 2.21s（后面那句还没合成好）          ← 有这行说明合成又追不上了
这一小句说完：5.44s 音频（收队 1.14s）        ← 括号里是写声卡等了多久（≈实时就正常）
流式收尾用了 1.2s（stop … / close …）          ← 超过 0.3 秒才打，说明声卡缓冲拖住了下一句
```

**`/say` 还有 0.5～1 秒的空档是正常的**：那条路是按整句切的，第一句往往只有
3.4～4.2 秒，盖不住 4.3 秒的合成（识屏走的是「前 3 段按标点切 + 第一段至少 24 字」）。
修 `/say` 就得让第一句也按逗号切，但对「整段念一句话」这种场景反而更碎，没做。

### 4.2i 多音字读错怎么办（2026-11-17 加，先从「弹幕→谈幕」查起）

### 4.2k 顺带修的崩溃：新识屏打断旧语音时进程直接没了（2026-11-17 01:36）

**症状**：连着两轮识屏（前一轮还在念），网关进程凭空消失，`stderr` 里没有 traceback，
客户端拿到 `ConnectionResetError`。事件查看器：

```text
Faulting application name: python.exe
Faulting module name: libportaudio64bit.dll
Exception code: 0xc0000005
```

**原因**：`interrupt()` 在**别的线程**里对新一轮的流式音频调 `stream.stop()`，而那条流的
写入线程正卡在 `stream.write()` 里。PortAudio 不允许这样并发，直接访问违例把整个进程带走。

**修法**：

1. `interrupt()` **不再碰 sounddevice 的流**，只翻 `generation` + 用 `winsound.PlaySound(None)`
   截断正在播的那句；写入线程下一块发现 generation 变了会自己退出，`_play_stream` 在自己线程里收尾；
2. 写和收尾共用 `stream_lock`，`stream.write()` 和 `stop()/close()` 永不并发；
3. 收尾前先 `writer_done.wait(3.0)`，等写入线程退干净；
4. `pcm_q.put(None)` 的超时从 5 秒改成 0.3 秒（打断时队列可能是满的，等 5 秒毫无意义）。

**验证**：anime 模式下连打两轮识屏，第二轮打断第一轮，进程活得好好的（`/health` 200），
日志里两句 `念(vision) …` / `流式开播 …` 都在。

| 画面参考 | 2×2 四帧 | **6 帧、3 列**（`frame_buffer.keep` 调到 8），提示词要求「连起来看，看到连招/极限躲/反打/一波清完就带着情绪说出来」 |
| 额外规矩 | 不剧透、不报进度 | 认得出游戏/角色就说名字；不报进度、不刷屏（**「不指挥」和「不念界面文字」两条 22:30 按老大要求删掉了**） |

> 22:30 那版改动：老大说「不指挥、不当教练」和「界面文字不许念」没必要，删了。

**2）模式锁：锁 N 分钟，到点**只放开、不退出**（老大 2026-11-17 改的语义）**

以前是「托盘选的模式满 10 分钟自动回 auto」，等于把选好的模式悄悄取消。现在的语义：

- 托盘选模式 → 记一个 `mode_lock_until = now + mode_lock_minutes`（**默认 5 分钟**）；
- **手动锁子菜单**还可以切「一直保持」：`Mode.lock_forever=true`，锁不到期，
  一直保持托盘勾的模式，直到勾别的模式（或「自动模式」）或改回 5 分钟；
- 锁住期间：VideoWatcher / GameWatcher 一律不许改动它（`_locked()` 检查 source 和 `mode_lock_until`）；
- 到点：只调 `Mode.release()` 把 source 从 `tray` 改成 `tray-released`，**模式本身不变**；
  之后按各自的退出判断来——游戏模式看窗口切走/游戏关掉，视频模式看播放停没停，
  番剧/直播/网课这种没有自动判定的就一直保持，直到手动换掉。

日志：`模式锁：anime 锁 5 分钟（到点只放开，不退出）` → `模式锁到期（锁到期），「anime」交回自动判定`。

**3）游戏模式自动进出（`GameWatcher`）**

- 判定是不是游戏：`titles.json` 里 `kind=game` 的作品命中，或者 `game_watch.game_apps` 里点名的进程；
- **进**：前台是游戏、连着稳 `enter_seconds`（默认 90 秒）→ `mode=game`（source `auto-game`）；
- **退**：切走/关掉超过 `away_grace_seconds`（默认 180 秒）→ 回 auto；
- **不看键鼠活跃度**（老大专门说了不要这个条件），也不管有没有声音；
- 托盘锁住的期间，这两个动作都不做。

配置：

```json
"mode_lock_minutes": 5,
"game_watch": {"enabled": true, "poll_seconds": 5, "enter_seconds": 90,
               "switch_seconds": 20, "away_grace_seconds": 180, "game_apps": []}
```

**4）作品小抄（titles.json）支持类型，自动补条目**

```json
"绝区零": {"kind": "game", "note": "动作游戏：编队三人…伙伴有安比、妮可、比利、猫又。"},
"甘城光辉游乐园": {"kind": "anime", "note": "游乐园快倒闭了，男主可儿江西也…"}
```

`kind` 现在**是「游戏模式自动进」的依据**（后台是游戏才进）；老写法（纯字符串）照样能读，
只是没有类型、不会触发自动进。`TitleLearner` 每 60 秒看一眼前台：同一个标题连着看到 2 次才问，
6 小时内不重复问，问出来带 `kind` 一起写进去。

关掉：`"title_learner": {"enabled": false}`。手动加：`POST /titles {"名字":"说明"}` 或
`{"名字":{"kind":"game","note":"说明"}}`。

### 4.2n 副本：番剧/直播/网课也走视频的退出判断 + 视频模式改「只吃声音」（2026-11-17）

**1）番剧/直播/网课的退出判断跟视频一样**

以前只有 `video` 有自动退出，`anime/live/course` 锁到期后就一直挂着。现在：

- 托盘锁在的时候（`source=tray` 或 `mode_lock_until` 未到）谁都不许动；
- 锁一放开（`source=tray-released`，`since` 重置）就开始判：**120 秒没声音在响**（`paused_away_grace_seconds`）→ 回 `auto`，日志
  `anime 模式：已经 121 秒没声音，回自动`；
- `VideoWatcher._leave()`（播放停了/窗口走了）现在也会把这四种模式一起重置，不再只管 `video`。

实测：选 `anime` → 锁 5 分钟 → `模式锁到期（满 5 分钟），「anime」交回自动判定` → 静音 10 秒（测试值）→
`anime 模式：已经 11 秒没声音，回自动`，`mode=auto source=video-leave`。

**2）B站视频模式是怎么知道「现在放到哪」的？**

**不是靠进度条，也没有「定位」**。它维护的是一个**滚动的对白窗口**：最近 N 条（`transcript_keep`，默认 12）
带时间戳的台词，识屏时整段塞给模型当剧情参考。素材有两个来源：

| 来源 | 做法 | 状态 |
|---|---|---|
| **环回转写（主路）** | WASAPI 环回录系统声音 → 每 8 秒一包 → 9881 转写 | 现在**只剩这条** |
| 字幕条 OCR（兜底） | 每 2 秒截屏幕下 1/3 → rapidocr 认字 | **默认关**（`subtitle_ocr: false`） |

**3）为什么 OCR 关掉、为什么只能靠声音**

老大说的没错：很多视频根本没做字幕条，OCR 白跑。所以：

- 新增 `video_watch.subtitle_ocr`，默认 true，但**只当兜底**：转写连续 60 秒没出词才开 OCR，
  转写一回来就自动关（日志：`视频模式：60 秒没转写出词，开字幕 OCR 兜底`）；
- 转写不像中文的（`asr_min_cjk_ratio` 以下，外文片/纯音乐/噪音）**直接丢掉**，不再塞给模型凑数；
- 想彻底不做 OCR 就设成 false（那就不起 OCR 进程）。

**4）顺手发现的两个真问题**

1. **蓝牙耳机的环回是哑的**（2026-11-17 实测）：放 440Hz 测试音，Realtek/NVIDIA 的环回 RMS ≈ 0.15，
   蓝牙耳机（iKF-King Pro⁺）**0.0003**——等于没声音。媒体跑在蓝牙上时，只录默认端点就一句都转不出来。
   改法：`AudioLoop` 现在**同时录 3 个端点**（默认 + 板载 + HDMI），按电平挑「真的在响」那一路送转写；
   连续 2 分钟全都没声会打一行警告：`环回已经 2 分钟没声音：媒体是不是在蓝牙耳机上？…`
   状态里能看：`/status` → `video.loopback`（正在录哪几个端点）、`video.last`（最后一句转写）。
2. **手动进通用视频会立刻退出**：`force()` 以前不设 `last_audio_at/last_fore_at`，下一轮 `_tick` 就以为
   「早就没声了、人也不在」，直接 `_leave`。现在补上了。

**结论**：她现在看视频**只听声音**（转写当剧情参考），不再依赖字幕条；如果你在蓝牙耳机上看，
要么把输出换到扬声器/HDMI，要么设 `video_watch.loopback_device` 指一个能录的端点。

### 4.2o 「扒 B站字幕 + 按播放进度切前面的字幕」——设计稿有，代码没有（2026-11-17 说明）

### 4.2p 方案 B 落地：B站视频模式按「播放进度」切字幕（2026-11-17 实现）

4.2o 记的是「设计稿有、代码没有」。**这一节是把它做出来了**，走老大选的方案 B（Edge 调试端口）。

**现在识屏时「视频上下文」的优先级**（新的退化链）：

| 顺序 | 来源 | 精度 | 需要什么 |
|---|---|---|---|
| 1 | **CDP 读浏览器**：`location.href`、`document.title`、`video.currentTime/duration/paused` | 秒级、实时 | Edge/Chrome 带 `--remote-debugging-port=9222` |
| 2 | **B站历史进度兜底**：`x/web-interface/history/cursor` 里的 `progress` | 晚十几秒 | `bili-cli/credential.json`（已登录，现成的） |
| 3 | 环回转写 | 每 8 秒一段 | 系统声音能被环回录到 |

历史兜底时会多一句「（进度取自 B站历史，可能晚十几秒）」，并且窗口自动放宽到 180 秒补滞后。

### 4.2q 方案 A（浏览器扩展）也做好了，现在是第一优先（2026-11-17）

老大试了 B 之后说「这方案好像不行，还不如 A」，于是 A 也做了。**两条并存，扩展优先。**

**扩展长什么样**：`D:\app1\paopao_pet_gateway\browser_ext\`（MV3，三个文件 + README）

| 文件 | 干什么 |
|---|---|
| `manifest.json` | 只在视频站生效：bilibili / YouTube / 爱奇艺 / 优酷 / 芒果 / 腾讯视频 / 抖音；只授权 `http://127.0.0.1:9888/*` |
| `content.js` | 每秒读一次页面里的 `<video>`：`url / title / currentTime / duration / paused / fullscreen / visible`，发给后台 |
| `background.js` | service worker 把收到的 POST 给网关 `/player`（放在后台是为了绕开页面跨域） |

**装它**（三下，不用重启浏览器）：`edge://extensions` → 开发人员模式 → 加载解压缩的扩展 → 选 `browser_ext`。

本机任务栏那个 Edge 快捷方式已经把 `--load-extension=…\browser_ext` 加进去了（原始参数备份在
`logs\edge-shortcuts-backup.json`），下次启动 Edge 自动带上；公共桌面那个因权限没改，不影响。

**网关这边**：`POST /player` 收上报，`PlayerWatch.push_ext()` 存一份；`GET /player` 返回当前状态给扩展自检。
现在是**四层来源**，优先级从高到低：

| 顺序 | 来源 | 精度 | 需要什么 |
|---|---|---|---|
| 1 | **浏览器扩展（A）** | 秒级 | 装一次扩展 |
| 2 | CDP 调试端口（B） | 秒级 | Edge 带 `--remote-debugging-port=9222`（默认配置开不了，见 4.2p） |
| 3 | B站历史进度 | 晚十几秒 | B站登录态（现成的） |
| 4 | 环回转写 / 字幕 OCR | 8 秒 / 2 秒 | 系统声音能被环回录到 |

拿到 bvid 之后的字幕流程跟 4.2p 一样（`bili video subtitle` + 90 秒窗口 + 本地缓存 24h）。

`bilibili.com/video/BV16cWd6pEBh`，2 秒内 `/status.player` 就变成：

```

title: 『原神』7.3前瞻日期确定…
```

**隐私边界**：扩展只报「地址、标题、进度、暂停、全屏、可见」，不读 DOM、不改页面、只发到 127.0.0.1:9888；
而且只在上面那七个视频站生效。

**排障**：`/status.player.connected=false` → 扩展没启用/页面不是视频站/视频没播；
扩展没装或关掉时会自动退到 CDP → B站历史 → 转写。


#### 4.2q.1 桌面快捷方式 + 给别人的一键装法（2026-11-17 补）

**为什么改的是「用户桌面」的快捷方式**：本机桌面那个 `Microsoft Edge.lnk` 实际在 **公共桌面**
（`C:\Users\Public\Desktop`），属主是 `BUILTIN\Administrators`，普通权限存不进去（实测
`Unable to save shortcut`）。所以做法是：**在用户桌面放一个同名 lnk**

#### 4.2q.3 播放进度上报：旧扩展已退役，现在用 Tampermonkey（2026-11-17）

**背景**：旧的 `browser_ext` 是 unpacked（开发人员模式）扩展。Edge 更新、配置目录重建、
或它自己把「开发者模式扩展」关掉，都会让扩展失效；默认配置下 `--load-extension` 又被
Edge 157 忽略。所以 2026-11-17 起：

- 删掉旧扩展的 `manifest.json` / `content.js` / `background.js`，**不再用开发者模式**；
- 主路改成商店扩展 **Tampermonkey** + `browser_ext/paopao-player.user.js`；
- `make-edge-shortcut.ps1` 只负责把旧快捷方式里的 `--load-extension` 清掉。

**现在有三层**：

1. **Tampermonkey 用户脚本（主路，推荐）**：Edge 加载项商店装 **Tampermonkey**
   （Violentmonkey / ScriptCat 也行），打开
   `http://127.0.0.1:9888/ext/paopao-player.user.js` 安装；Edge 157 还要在
   `edge://extensions` → Tampermonkey「详细信息」里打开「允许用户脚本」。商店扩展不会被
   「开发者模式扩展」那套清掉。
2. **看片窗口（CDP 兜底）**：`start-edge-watch.ps1` 用独立配置目录 +
   `--remote-debugging-port=9222`，不依赖任何扩展；扩展/脚本没跑时
   `PlayerWatch.snapshot()` 从 CDP 读 URL/currentTime，再退到 B站历史。
   > 看片窗口已经开着的话，先关掉再重跑脚本，`--remote-debugging-port` 才会生效
   > （同一个配置目录已有 Edge 进程时，新参数会被忽略）。
3. **主浏览器没有 URL 时**：模式判定仍会按**窗口标题**走
   （`哔哩哔哩` / `番剧` / `第X集` / `直播` 都能认），所以切模式不会卡死；
   只是没有精确进度和按时间轴的字幕，B站历史兜底还能补最近的 bvid/进度。
4. **永久方案（要管理员一次）**：把用户脚本/扩展打成 CRX，配 Edge 企业策略
   `ExtensionInstallForcelist`（`<扩展ID>;http://127.0.0.1:9888/ext/update.xml`），
   由网关提供 `update.xml` + `.crx`。force-install 的扩展不会被 Edge 更新/开发者模式清掉，
   也不需要用户点「加载解压缩的扩展」。代价是要写一次 HKLM 策略、且扩展更新要走本地源。
4. **免开发者模式（不需要管理员，推荐先试）**：装商店里的 **Tampermonkey**（或 Violentmonkey /
   ScriptCat），把 `browser_ext/paopao-player.user.js` 装进去。最省事是 Edge 打开
   `http://127.0.0.1:9888/ext/paopao-player.user.js`（网关直接吐脚本，Tampermonkey 弹安装页）。
   **Edge 157 / Chromium 138+ 还要在 `edge://extensions` → Tampermonkey「详细信息」里打开
   「允许用户脚本 / Allow user scripts」**，不开脚本不执行；第一次会问是否允许访问
   `127.0.0.1:9888`，点允许。宿主是商店扩展，不会被「开发者模式扩展」清掉；脚本本身存在
   Tampermonkey 里，可导出备份。

**别做的事**：手改 Edge `Preferences`/`Secure Preferences` 里扩展的 `state`——
Edge 下次启动会按自己的策略覆盖，轻则被禁，重则整个扩展设置被清；要持久只能走 CRX + 策略。

> **B站隐藏 iframe 会把真实进度覆盖掉（2026-11-17 实测）**：B站页面里有一个
> `message.bilibili.com/pages/nav/header_sync` 的跨域 iframe，旧用户脚本/扩展会在里面也跑，
> 每秒把 `header sync / 0:00` 写进 `/player`，导致 `player.url` 变成 header sync、模式看着像失灵。
> 修法两层：用户脚本 1.0.2 不再限制顶层，而是**只在真的有 `<video>` 且 `currentTime` 是数字的帧**
> 上报（隐藏 iframe 没 video 自然被挡；B站直播/番剧播放器即使在 iframe 里也能报）；
> 网关 `PlayerWatch.push_ext()` 只认带有效 `currentTime` 的上报，没有时间戳的一律丢弃——
> 不只 B站，YouTube/爱奇艺/腾讯/抖音的隐藏 iframe 也走同一条规则；直播的 `duration` 是
> `Infinity` 也没关系，只要 `currentTime` 是数字就收。B站直播/番剧若在 iframe 里，
> 网关会用 `referrer` 里的 `live.bilibili` / `bangumi` 补判。

     每个新角色一次图片调用，单次版本最多补 4 个；找不到立绘就只留身份；
   - `latest` 最多 5 条，注入有 520 字上限；`/status.game_versions` 可看当前版本。



### 4.2r 识屏的三件事：说清「现在在干嘛」、别按「第几张」讲、角色别认错（2026-11-17）

**1）模式状态写在最前面**

老大原话：「在看番/识屏/玩游戏模式，要告诉她用户现在正在看番/在看/玩游戏，游戏模式让她陪玩」。
`build_watch_focus()` 现在第一行就是【此刻】：

| 模式 | 注入的第一句 |
|---|---|
| anime | `【此刻】老大正在**看番**（你陪着他一起看），不是在做别的事，也没在跟你闲聊。` |
| video / live / course | 同理，分别写「看视频 / 看直播 / 上网课」 |
| game | `【此刻】老大正在**打游戏**，你是坐在旁边陪玩的那只鲸鱼娘——不是观众，也不是解说。` |

后面才是「陪看/陪玩的规矩」（不提时间、不念字幕、不剧透、不指挥…）。

**2）不许说「第几张」**

帧拼图会给她 4～6 张连续画面，她以前会说「第一张里是……第二张里是……」。
`build_see_howto()` 和游戏模式都加了硬规矩：

> **给你的是几张连续画面（帧），当一段动作看**：不要用「第一张」「第二张」「第几张讲了什么」这种说法，
> 也不要把它们当成几张不同的图分别描述；只说你从这几秒里看出来的事。

**3）角色别认错：**（2026-11-17 晚**已撤掉**）

本来做过一版 `characters.json` + 聊天里自动学「蓝头发的女孩 = 三月七」，识屏和语音问答都会注入
「【角色对照…】看到『…』就是 **三月七**」。老大用下来发现副作用：**只要话题沾到角色，
她就会把这两条主动抖出来**（「这不是紫头发双马尾啊？也不是蓝头发的三月七」），很出戏。

所以整块拆了：`characters.json`、`learn_characters`、注入逻辑、`save_character()` 全删了，
配置里也没有这几个键了。角色认不认得全靠模型自己看图 + 小抄里的「主要人物」，
认不出就只说外形（`see_howto` 里那条规矩还在）。


### 4.2s 她偶尔说「截到黑屏」——是截屏问题，不是屏幕真黑（2026-11-17）

**结论先说**：**这台机器上截屏本身没失效**——老大 2026-11-17 试过，游戏独占全屏她也能看见，
帧缓冲抓得到。所以黑屏是**偶发的那几帧**，常见于：

| 场景 | 为什么那几帧是黑的 |
|---|---|
| 切窗口 / 切分辨率 / 加载黑场 | 合成层那一刻是空的 |
| 锁屏 / 息屏 / 显示器断电 | 抓到的是空桌面 |
| DRM 保护的片源（Netflix 等） | 系统层面就不让截（这类会一直黑） |

也就是说：**不是抓不到，是赶上了那一瞬**。所以兜底策略偏「换一张」而不是「干脆不看」：
桌宠那张黑了就换我们 10 秒内的好帧，只有连续 2 张都黑才整轮跳过。

桌宠自己用哪套抓屏我们改不了；但**我们的帧缓冲截的是同一块屏幕**，所以能做三层兜底：

1. **黑帧不进缓冲**（`FrameBuffer`）：每帧顺手算「亮度 < 24 的像素占比」，≥ `black_ratio`（默认 0.92）
   就只记比例、不进拼图、也放慢采样（黑屏本来就不该被当成「画面变了」）。
2. **请求里那张图黑了就换掉**（`Gateway.fix_black_request_image`）：桌宠传上来的「此刻屏幕」
   如果 ≥92% 是黑的，而我们帧缓冲里有一张 10 秒内的好帧，就**用我们的 JPEG 顶掉它**，模型看到的
   就是真画面。日志：

```text
识屏：请求里那张图有 100% 接近纯黑
识屏：桌宠那张图是黑的，用我们自己截的换掉了
```

3. **两边都黑就整轮跳过**（`vision_is_black`）：连续 `vision_black_frames`（默认 2）张都 ≥92% 黑 →
   这一轮**不叫模型、不说话、不冒泡、不记账本**，只打一行
   `识屏：这一帧太黑（100% 接近纯黑），跳过这一轮`。回给桌宠的是一个空的完成，它安静收场。

配置（`config.json` 顶层）：

| 键 | 默认 | 说明 |
|---|---|---|
| `skip_black_frames` | true | 黑屏守卫总开关 |
| `vision_black_ratio` | 0.92 | 多黑算黑（0~1） |
| `vision_black_frames` | 2 | 连续几张才算（防一帧闪烁误判） |
| `fix_black_request_image` | true | 桌宠那张黑、我们截得到就换掉 |
| `frame_buffer.black_ratio` | 0.92 | 帧缓冲自己的判黑阈值 |

**实测（2026-11-17 04:17）**：伪造一张全黑 JPEG 当「此刻屏幕」发一次识屏，
日志打出上面两行，回复描述的是真实画面（「白发红裙、头顶黑红小冠的姑娘」），没有出现「黑屏」。

**老大侧能做的**：其实不用改无边框窗口——实测独占全屏也能抓到（见上）。真一直黑只有两种可能：
① 片源有 DRM；② 那几秒屏幕真的没画面（锁屏/黑场）。这两种跳过是对的。

### 4.2u 语音问答也带一张截图：取「开口那一刻」的帧（2026-11-17）

老大要求：按键说话/语音电话也要给她一点画面素材，「可以只一张」；拍的应该是**开口那一瞬间**，
不是说完；还得在提示里说清「这不是现在的」，并标上大概几秒前，免得她当成很久以前的图。

**做法**（不改截屏节奏，零额外延迟）：

1. `voice_mode.py` 的 VAD 在**第一个超过能量阈值的音频块**记下 `last_onset_at`（就是你张嘴那一刻）；
2. `voice_reply()` 按 `voice.screenshot` 决定要不要图：
   - `always`（默认）：每句话都带一张；
   - `auto`：只在问到屏幕相关（原来的 `LOOK_HINTS` / 模式是看片打游戏）时才带；
   - `off`：不带。
3. 取图**从帧缓冲里挑离 `last_onset_at` 最近的那一帧**（每秒本来就在截，黑帧已经被丢掉了），
   不额外触发一次截屏——所以不会为了这张图多等；
4. 提示词变成：`这张是你开口说话那一刻的屏幕，大约 N 秒前——不是现在的。这期间画面可能已经变了，
   别把它当此刻，也别拿它当「很久以前的图」。`
5. 日志：`语音：带上开口那一刻的帧（3 秒前）`。

**为什么只一张、不拼两张**（讨论时的结论）：两张 token 和延迟都翻倍，模型还得先分清哪张是开始；
真需要「变化」的场景（「刚才那波怎么样」）可以以后再加，默认一张就够。

**实测（2026-11-17 04:49）**：PTT 问「我现在在玩什么游戏？」，
回答直接描述了当时画面里的角色（白毛姑娘在屋里跑腿），没有出现「黑屏」或「看不到」。

配置：`config.json` → `voice.screenshot`（`always` / `auto` / `off`）。

### 4.2v 让她真的「认识」一款游戏：自己查资料、自己总结、按需查（2026-11-17）

老大的要求：**「怎么让她可以彻底认识一款游戏（或者尽量）」**，而且
**玩家手册不要他写，得她自己搜、自己总结**。

4.2r 那套「作品小抄」只够她说一句「哦，这是绝区零」，再往下问玩法、术语、界面、角色就露馅；
而把大段百科常驻塞进提示词，她会逮着刚学到的名词乱抖（角色对照就是这么翻车的）。
所以这次做的是两层：**本地手册 + 按需检索**，平时一个字的资料都不注入。

#### 4.2v.1 目录与格式

```
lore/
  games/<slug>.md      手册正文：<!-- paopao-lore {...} --> 元数据 + # 作品名 + 固定小节
  progress/<slug>.md   老大在这款游戏里的进度/偏好（从识屏账本提炼）
  raw/<slug>/*.txt     抓到的原料（留档，最多 6 份）
lore.py                模块：抓取 / 总结 / 分块 / 检索 / 后台补课 / 命令行
```

游戏小节：`一句话` / `怎么玩` / `操作与战斗` / `界面长什么样` / `术语黑话` / `角色` /
`版本沿革`（不带日期的版本改动）/ `时效`（只放带日期、能过期的）；
番剧小节：`一句话` / `讲的是什么` / `主要人物` / `梗和术语` / `时效`。
元数据里带 `name`、`kind`、`aliases`（进程名、英文名、带不带冒号都记上）、`updated`、`sources`。
**改了文件不用重启**：`Store` 按 mtime 自动重载。

#### 4.2v.2 资料从哪来（都是她自己去抓的）

| 来源 | 怎么拿 | 备注 |
|---|---|---|
| 萌娘百科 | `action=query&prop=extracts&explaintext=1&redirects=1` | 只用这条。`list=search`、`parse&prop=links`、`categorymembers` 在本站**要么被拒（Unauthorized API call）要么返回空**，别浪费时间 |
| B站攻略 | `bili --compact search video "<名字> 新手 攻略"` + `"<名字> 玩法 机制"`，再 `bili --compact video watch <bv> --max-chars 2400 --comments 0 --peaks 0 --frames 0 --no-danmaku` | 拿 AI 摘要 + 章节 + 字幕摘录；番剧不抓 B站（容易剧透） |
| 原料留档 | `lore/raw/<slug>/时间-来源.txt` | 以后想重总结不用重新抓 |

选片规则（不这么筛就会搜到 EP、英语单词教学、二创、直播切片）：

1. 标题里必须出现作品名；
2. 命中正向词：攻略/新手/萌新/入坑/教程/指南/机制/玩法/介绍/开荒/教学/怎么玩；
3. 排除负向词：英语、单词、音乐、ep、主题曲、翻唱、钢琴、mmd、手书、二创、同人、剪辑、混剪、
   直播回放、切片、电台、asmr、声优、cosplay、整活、鬼畜、角色演示、pv、预告、版本前瞻；
4. 时长 90 秒～50 分钟（太短没内容，太长多半是整活/直播）；
5. 两路关键词合并去重，先按「正向词命中数」再按播放量排，取前 `bili.videos`（默认 2）。

**试过但没接的源**（别再走一遍）：

- **BWIKI**（`wiki.biligame.com/<子域>/api.php`）：API 能通（`ys`、`zzz` 都试过），但**一款游戏
  一个子域**，得先知道映射；返回的是 wikitext，模板/表格噪声很大，还要再洗一遍。萌娘 + B站
  已经能覆盖「玩法/术语/界面/角色」，先不接。
- **Bangumi API**（`api.bgm.tv`）：本机直接超时（网络不通），番剧只走萌娘百科。
- **萌娘百科的搜索/分类/links API**：`list=search` 返回 `Unauthorized API call`，
  `list=categorymembers`、`parse&prop=links` 返回空——别指望用它们发现角色页或别名。

#### 4.2v.3 总结：用 chat 模型，不要用推理模型

`Lore.summarize()` 调 `gateway.post_once()`，模型是 `lore.model`，**默认 `deepseek-chat`**。

为什么不用 `deepseek-v4-flash`：它是推理模型，思考 token 也算在 `max_tokens` 里。实测同一份
10k 字原料，`max_tokens=1600` 时 **1290 个 token 花在思考上，正文只有 410 字就被截断**；
再加到 3000 也只出 824 字。换成 `deepseek-chat` + `summarize_max_tokens=2400` 后完整出 1000+ 字。

**日期防编造**：提示词里只要出现一个示例日期，模型就会把它抄进「时效」的所有行（第一版 9 条
全是当天日期）。所以有 `sanitize_dates()`：把原料里**真实出现过**的日期收成一个集合
（支持 `2026-03-12`、`2026/3/12`、`2026年3月12日`），手册「时效」里对不上的日期直接抹掉；
宁可这条没日期，也不留假日期。

带日期的时效条目超过 `stale_days`（默认 60 天）就在分块时丢弃；没日期的版本改动放在
`版本沿革` 里（历史事实，不会过期），`时效` 只放带日期、会过期的。

#### 4.2v.4 检索：为什么不会每轮「报菜名」

- **BM25 + 中文 bigram**，不装分词库；英文/数字按整词。
- **停用词**：什么、怎么、这个、意思、今天……这些问句万能词不参与算分。
- **小节优先**：问句命中 `角色/人物/界面/术语/黑话/玩法/操作/战斗/版本/时效/卡池/剧情` 时，
  把同名小节直接提到结果最前面（`HEADING_WORDS`）。不然「角色」两个字在别的段落出现两次，
  就能把真正的「角色」小节挤下去。
- **作品名不进正文索引**：否则「只有标题、没有问话」时每一段都能命中，她每轮随机抖三条资料。
- **实词门槛**：`block()` 要求问话里至少 2 个非停用词，只有标题就返回空。
- 当前正在玩的作品加权 1.35。

#### 4.2v.5 什么时候注入（这一节是「不乱说话」的关键）

| 场景 | 给什么 |
|---|---|
| 识屏 + 有问话/相关线索 | 最多 3 段（预算 520 字），带「用不上就一个字都别提，别背、别报菜名」 |
| 识屏 + 游戏模式 + 没问话 | 只给 `headline()`：那一句「这是什么游戏」，不给大段 |
| 识屏 + 自动模式 + 没问话 | **什么都不给**（避免她闲着也报菜名） |
| 语音问答 | 最多 3 段；问到没学过的作品会顺手排队补课，并提示「这款你还不太熟，别装懂」 |
| 聊天里提到学过的作品 | 2～3 段（没提到就一个字不加） |
| 不认识的作品（前台有标题） | 只提示「还不熟，别编」，不会硬编 |

注入文案固定带三句：这是你自己攒的笔记、只挑有关的一两条、用不上别提。

  - 启动时 `prebuild`：把 `titles.json` 里 `kind=game/anime` 的条目排上队（第一次启动会一本一本补，
    每本十几秒到一分钟，**不是没反应**）；

### 4.2w 三个「声音/认人」问题（2026-11-17）

老大一次报了四个现象：切「关闭」说「行，不看了」有两个声音、通用视频用的是 B站视频的提示、

#### 4.2w.1 「行，不看了」为什么说两遍

不是预存的锅，是**两条路都在发声**：

1. `Mode.set("off")` → `_announce_mode()` 随机挑 `MODE_PHRASES["off"]` 说一句（日志 `念(mode) 1 句 / 6 字`）；
2. 紧接着 `_handle_mode()`（托盘关闭）或 `_proactive_sync_loop()`（桌宠开关关掉）
   又补一句 `PROACTIVE_OFF`（就是「行，不看了」，日志 `念(mode) 1 句 / 5 字`）。

两条都对、但只该留一条。修法：

- `_announce_mode()` 看到 `source == "pet-proactive"` 直接返回：开关联动的提示由
  `_proactive_sync_loop()` 自己发（开 → 「主动识屏已开启…」；关 → 气泡 +「行，不看了」）；
- `_handle_mode()` 托盘关闭**不再**补 `speech.say(PROACTIVE_OFF)`；
  只有 `mode_feedback=false`（模式提示被关掉）时才兜底补这一句。

现在三条路径各自只有一次 `念(mode)`：

| 操作 | 日志 |
|---|---|
| 托盘「关闭」 | `模式提示：行，不看了。（off / tray）` + `念(mode) 1 句 / 6 字` |
| 桌宠开关关 | `桌宠关掉主动识屏 → 关闭` + `念(mode) 1 句 / 5 字` |
| 桌宠开关开 | `桌宠打开主动识屏 → 自动模式` + `念(mode) 1 句 / 22 字` |

实测 2026-11-17 14:00：三条路径都只出一次声，没有再叠。

#### 4.2w.2 通用视频要自己的两句

`video` 这个 mode 被「B站视频」和「通用视频」共用，以前提示统一是
「哦，刷B站视频啊。」，老大在看本地播放器/别的网站时听着不对。

改法：`phrases.py` 加一组 `video_any`（两句），`_announce_mode()` 按 `source` 选：

```python
key = mode
if mode == "video" and source in ("tray-generic", "auto-video"):
    key = "video_any"
```

| 场景 | source | 预存句子（随机二选一） |
|---|---|---|
| 托盘「通用视频」/ 自动判定播放器 | `tray-generic` / `auto-video` | 「哦，看视频呢，我陪你一块儿看。」「行，那我跟着你看会儿。」 |
| 托盘「B站视频」/ 扩展报上来的 B站 | `tray` / `api` | 「哦，刷B站视频啊。」「哦，B站视频啊，我跟你一块儿看。」 |

新句子会被 `warm_fixed_phrases()` 在启动时补合成；不重启也可以 `POST /warm {"force":false}`
只补缺的。实测托盘「通用视频」日志：`模式提示：行，那我跟着你看会儿。（video / tray-generic）`。

#### 4.2w.3 一开始识屏没声音

**根因有两个，叠在一起**：

1. 开机时网关先起来，GPT-SoVITS 还在加载（60~90 秒），这期间所有 TTS 请求都连不上；
   `_request_audio()` 原来只重试 3 次、间隔 0.4 秒，等不到它加载完，整句直接丢；
2. `ensure_running.ps1` 在 Windows PowerShell 5.1 下解析失败——文件是 **UTF-8 无 BOM**，
   中文注释被当 ANSI 读，某些字节被解释成行尾反引号，把下一行代码吞了，
   于是 `$logDir`/`$marker` 是空的，守护脚本根本没拉起 TTS。
   表现就是日志 `Test-Path : Cannot bind argument to parameter 'LiteralPath' because it is an empty string`。

**修法**：

1. 网关目录下所有 `.ps1` 补 UTF-8 BOM（`ensure_running.ps1`、`watchdog.ps1`、`follow_pet.ps1`）；
2. 新增 `TtsGuard` 线程（`gateway.py`）：
   - 每 `tts.guard.check_seconds`（默认 15s）探一次 TTS 端口；
   - 没在跑就按 `tts.guard.launch` 里的 python/script/args/workdir 拉起来，
     并写 `logs/.gsv-started`（`ensure_running.ps1` 看到它 3 分钟内不会重复拉）；
   - `GET /status` 有 `tts_guard`，`GET /doctor` 多一项 `tts_guard`；
3. `SpeechPipeline._wait_tts()`：TTS 连不上时不立刻重试，先让 guard `ensure(timeout=25)`
   （没起就拉、正在加载就等），再重试；流式和整句合成两条路都加了。
4. 兜底：`_handle_mode` 的关闭提示只在 `mode_feedback=false` 时补。

`TTS 没在跑，拉起 GPT-SoVITS（pid 11132）` → 17 秒后 `TTS 已就绪（等了 17 秒）`，
`/status` 的 `tts_guard` = `{"up": true, "launches": 1}`。

### 4.2x 自动切换与托盘同步：一次修一批（2026-11-17）

老大用着觉得「一堆问题」，实测下来确实是几处独立的小毛病叠在一起：

| 现象 | 根因 | 修法 |
|---|---|---|
| 托盘选了「玩游戏」，托盘勾还是「自动模式」 | `bubble_host._apply_status` 只映射了 off/anime/video，`game/live/course` 全落到 auto | 抽成 `watch_key(mode, source)`；托盘仍只保留六项，`live/course` 统合显示成「B站看番」 |
| 选了「通用视频」，5 分钟后自动判定再也不动 | `_mode_lock_loop` / `Mode.release` 只认 `source == "tray"`，`tray-generic` 永远不释放 | 改成 `startswith("tray")`；release 保留身份：`tray-generic` → `tray-generic-released` |
| 通用视频锁到期后，托盘跳回「B站视频」 | release 把 source 统一写成 `tray-released`，丢了 generic | 同上，release 带 `-generic` 后缀 |
| 自动进 B站 也显示「通用视频」，分不清看番/直播 | 自动判定统一写 `auto-video`，托盘只能当通用 | `VideoWatcher._video_target()` 按 URL/标题区分 `auto-anime` / `auto-video-bili` / `auto-video`；直播也归到「B站看番」，托盘只勾这一项 |
| 从视频切游戏（或反过来）要等 5 分钟 | `GameWatcher` 只在 `mode == auto` 时进；`VideoWatcher` 在 game 模式直接 return | 两个方向加「自动模式接管」：`switch_seconds`（默认 20 秒），只接管 `auto-*` 来源，手动锁不碰 |
| 托盘选「B站视频」后要等 2 分钟才进会话 | 只有 `tray-generic` 调了 `video.force()` | 所有托盘视频类（video/anime/live/course）都 `video.force()`，立即开会话 |
| 网关重启后出现两个托盘图标 | 旧 `bubble_host.py` 进程的 stdin 没断干净，新网关又拉起一个 | `bubble_host` 写 `logs/bubble_host.pid`；`BubbleBridge._spawn()` 先 `taskkill` 旧 pid 再拉新 |
| 网关重启后她那边开着主动识屏，模式却停在 off | 启动只处理「她关 → 我关」，不处理「她开 → 我开」 | `_proactive_sync_loop` 首次同步补反向：off + `pet-proactive` 来源 → auto |

**托盘「自动模式」既是通用模式、也是自动判定入口（2026-11-17 澄清）**：内部 mode 值还是 `auto`；
它不只是一个“普通模式”，也负责让自动判定切到视频/游戏。所以 **5 分钟档不锁它**——锁 5 分钟会让
自动切换卡太久；只有手动锁切到「一直保持」时才把它也锁住，停在自动/通用状态不切换。
要让它继续自动判定，把手动锁改回 5 分钟即可。

**接管规则（不碰手动锁）**

## 9. 主动识屏（2026-11-15 凌晨调好）

源码事实（pet/proactive/__init__.py）：
**观察器只在 enabled==True 且 whitelist 非空时才运行**——白名单是空的，功能就是死的，
设置页里那个开关怎么点都不会有反应。

白名单规则（match_process_whitelist）：大小写不敏感的 fnmatch，**默认只匹配进程名**；
想按窗口标题匹配必须显式写 title:关键词。

**不限制（*）的取舍**：好处是换什么程序她都在看；代价是隐私面变大——
任何前台窗口都可能被截图并发给 DeepSeek API（密码管理器、银行、私聊、敏感文档都算），
而且她每 2 分钟就能开口一次（当前 cooldown 2 分钟、**日上限 9999 = 不限量**），
会比较吵、也更费 token。
白名单**只支持正向 fnmatch，没有否定规则**，所以做不到「全开但排除某几类」；
真要排除只能改成显式列举。

当前值（proactive_screen）：

| 键 | 值 | 说明 |
|---|---|---|
| enabled | true | |
| whitelist | * | 2026-11-15 起不限制：任何前台窗口都可观察。见下方取舍 |
| dwell_seconds | 15 | 同一窗口停留多久才开始观察（原 20） |
| cooldown_minutes | 2.0 | 两次之间的冷却（原 3） |
| min_request_interval_seconds | 60 | 请求最小间隔 |
| change_threshold | 5 | 画面变化（dHash）阈值，越小越敏感（原 8） |
| **daily_cap** | **9999** | **每天上限 = 不限量（2026-11-17 改；原来是 60）**。看片/打游戏一坐一两小时，60 次不够用；9999 之后不会再因为「今天看够了」突然不吭声 |
| pre_cue | false | 2026-11-17 起关掉：不再先冒「让我看看」气泡 |

> **改法（UI 上限不够时）**：直接改文件 `%APPDATA%\dsh-pet-standalone-webm-chat\config.json`
> 里的 `proactive_screen.daily_cap`，写成 **9999** 就等于不限制。写完存盘立刻生效（桌宠有
> QFileSystemWatcher 热重载，不用重启）；网关自己写这个文件时会保留其它键，不会把它改回去。
> 排查是不是被上限卡住：日志里出现「已达到每日上限」之类就不再看屏了，看一眼这个值就行。

实测 02:01 在 Edge 上主动识屏成功（她说「老大，你刷这个视频刷得挺入迷啊…」），
有语音（precue + 正片），也投进了记忆信箱。

已知 bug（桌宠自身，改不了）：识屏问答写回会话时会失败
（sync_look_to_chat → AttributeError: 'PetInstance' object has no attribute '_identity_config'），
所以识屏内容**进不了聊天记录**。上下文由网关的识屏账本 + 记忆信箱兜住。

### 6.8 识屏记忆怎么写才问得出来（2026-11-15 修）

**症状**：数据明明进了中枢，在 QQ 里问「我在干嘛」她答不上来。

**不是没通，是检索不出来。** 三个原因叠在一起：

1. **单条识屏不走总结**。当初为了省 token 写的是「单条直接拼原文」，
   而识屏基本都是单条（间隔超 120 秒），于是永远走不到总结那一步，
   存下来的是「老大框选屏幕给我看，前台是 StarRail.exe｜崩坏：星穹铁道」这种机器视角。
2. **总结提示词没要求回答「老大在干嘛」**。即使走了总结，也只写「看到了什么、我说了什么」。
3. **短问句召回差**。实测：「老大刚才在玩什么」查得到，「老大在干嘛」查不到 —— 就三个字，语义太虚。

**四处在生活桥里修掉了**：

| 改哪 | 怎么改 |
|---|---|
| 单条识屏 | **也走总结**，不再直接拼原文 |
| 总结提示词 | 第一句**必须**写「老大正在玩/在改/在看什么」，明确禁止「框选屏幕给我看」这种写法 |
| 输入清洗 | 「参考元数据：前台应用 Code.exe \| Visual Studio Code」→「老大正在用 Visual Studio Code」（取 `\|` 最后一段，去掉 `.exe`） |
| 检索 | 短 query 自动带扩展词（「老大正在做什么 在玩什么 在看什么」）；QQ 私聊问「在干嘛」时额外补一条最近的桌面识屏 |

**改完之后存下来的是这样**：

```
【桌面上｜老大在做什么】老大正在玩《崩坏：星穹铁道》。我趴在桌角晃着尾巴看，
屏幕上的血线看得我尾巴都绷直了，满屏跳着 1441 的奶量…
```

注意标签也从「桌面上看到」改成了「**桌面上｜老大在做什么**」—— 标签本身参与检索，
写清楚用途才认得出来。

**验证**（不用等，随时可跑）：


新的会自然替换掉它）。

**踩过的坑**：前面几轮只验证了「写进去」，没验证「问得出来」，结果到老大用的时候才发现。

### 6.9 识屏记忆带时刻（2026-11-15 再补一刀）

**症状**：问她「我在干嘛」，她把两个时间段的事都说了。因为一晚攒好几条，她看不到先后。

**修法**：记忆内容里直接带时刻。

```
【桌面上｜老大在做什么·02:38】老大正在改 AstrBot 跨平台记忆互通方案的代码…
```

配套两处：

- `recall_private` 的注入头里写明：「每条开头【…·HH:MM】是发生的时刻。有人问『我在干嘛』
  这类，**只回答最新那条**，不要把这几个时间段都列出来。」
- QQ 侧补桌面识屏时只补**最新两条**（`_recent_pet_vision(limit=2)`）——补多了她更会一条条列。

**注意**：`memory_companion` 自己的注入（QQ 侧的主要通道）不吃这个提示，
但它能看到记忆里的 `·HH:MM`，多少有帮助。真遇到她还在列，就是那边注入塞了多条。

### 6.10 问「我在干嘛」还是答成旧的（2026-11-15 二次修）

**症状**：中枢里明明有 21:58 的识屏摘要，QQ 里问「我现在在干嘛」还是答成几小时前、甚至昨天的。

**原因**：读写不是一套排序。生活桥取「最近的识屏」走的是 `bridge_search`
（语义检索），而识屏摘要的措辞几乎一模一样（都是「老大正在…」），语义检索
在一堆近似文本里挑的是**最像的**，不是**最新的**——21:58 和 19:19 谁被选中全看
措辞，结果永远轮不到刚发生的那条。

**修法**：问「在干嘛 / 在做什么 / 在玩什么」时不再走语义检索，直接按
`occurred_at` 倒序取 `memory_type=pet_vision_digest` 的最近两条
（`_latest_pet_vision_items()`，12 小时内），**提到注入内容最前面**。

| 改哪 | 怎么改 |
|---|---|
| QQ 侧 | `_provider_read` → 「外部记忆参考」里补最新 2 条桌面识屏 |
| 桌宠 / DSH 侧 | `recall_private` 把最新 2 条放最前，语义检索结果排后面 |
| 网关 | `own_look()`（自己看一眼那条路）过去不投记忆信箱，现在也投；否则「我们看的」永远进不了 QQ 那边 |

**注意**：识屏摘要是攒批的（默认 4 条、或停 120 秒才写一条），所以「刚刚看的那一眼」
最多晚两分钟才进中枢。要更实时就把 `paopao_life_bridge` 配置里的
`pet_vision_summary_items` / `pet_vision_summary_idle_seconds` 调小。

**验证**（重启 AstrBot 后随时可跑）：


## 11. 五档行为设计稿（2026-11-15，先设计后实现）

### 11.1 统一管线

所有模式共用一条管线，只有「素材从哪来」不同：

1. **状态层**：`/player` 每秒上报（浏览器扩展或调试端口）→ 会话对象
   `{url, app, title, started_at, currentTime, paused, playing, visible}`
2. **判定层**：normal / video / anime / live / course（+ off），带**进入门槛**（见 11.2）
3. **素材层**：按模式组装（见 11.3~11.7）
4. **注入层**：固定四段顺序 —— 这是什么 → 更早的摘要 → 刚才 90 秒 → 当前帧；
   并写死禁令：不剧透、不复述、别老说自己
5. **记忆层**：账本（24h）／段摘要（当次）／追番进度（长期）／集末简介回顾（看完才用）
6. **说话层**：沿用现有 TTS 流水线；`off` 模式只记账不念
7. **退化链**：字幕拿不到 → OCR；OCR 读不到 → 帧拼图；转写挂了 → 只看画面

### 11.2 进入门槛（解决「看两分钟就走」的浪费）

花费分两种，别混为一谈：

- **token（模型侧）**：每轮 700~1400 tokens，2 分钟一轮，看 3 分钟只有 1~2 轮 ≈ 2k tokens，**不贵**。
- **准备成本（本地/网络）**：抓字幕 5~15 秒、OCR 定位字幕带 1.5~2.7 秒、开转写、建会话状态。
  **短停留会把这些白做**，这才是浪费的大头。

所以用**两段式：探测 → 激活**。

**探测（零成本）**：只记「这个 URL 从什么时候开始」，不算 token、不抓字幕、不做 OCR。

**激活条件（全部满足才进模式）**：

| 门槛 | 默认 | 说明 |
|---|---|---|
| 同一 URL 连续停留 | ≥ 120 秒 | 切走或暂停超过 30 秒就清零 |
| 前台是浏览器/播放器 | 是 | 后台播放不激活（只记账） |
| 视频时长（二次闸） | **≥ 停留门槛**（默认 120 秒） | 总时长比门槛短的，根本不可能停留满，直接不进；URL 里有 bvid 就查一次时长 |

**不到门槛**：按 `normal` 处理（帧拼图 + 同 App 近况），不抓字幕、不开转写。

**离开检测（宽容版，别一去回 QQ 就断）**：

| 情况 | 宽限 | 处理 |
|---|---|---|
| 前台切走，但视频**还在播** | **5 分钟** | 不退出，标记 `away`，暂停主动说话；回来继续原会话 |
| **暂停**（前台还停在播放器上） | **10 分钟** | 可能只是去倒杯水；回来接着算 |
| **暂停**（前台已切走） | **2 分钟** | 大概率不看了，超时就结算 |
| **URL 变了 / 播放器关了** | **2 分钟** | 可能是切个标签马上回来；超时才结算退出 |

判据是「**还在不在播**」+「**前台的窗口还是不是它**」，不是「浏览器在不在前台」——
去回个 QQ 消息不该让整段会话作废。

判据是「**还在不在播**」，不是「浏览器在不在前台」——去回个 QQ 消息不该让整段会话作废。

**进入后立刻切走的兜底**：激活后 60 秒内就离开 → 这一轮**只写账本、不出声**
（免得她说了句「这片子不错」，你已经走了）。

### 11.3 normal（平时）

- 触发：桌宠自己的观察器（白名单 + 变化阈值 + 冷却）
- 素材：帧拼图（前 4 帧 2×2）+ 当前帧 + 同 App 近况（600 字预算）+ 定时摘要
- 节奏：沿用现有设置（1.5~2 分钟）
- 记忆：账本；摘要每 3 小时滚一次
- 退化：无

### 11.4 video（普通投稿 / 直播回放页）

- 触发：激活条件满足，URL 是 `/video/BV…`
- 素材：**前 90 秒字幕**（yt-dlp `ai-zh` 优先，OCR 兜底）+ 该视频滚动摘要（≤300 字）+ 当前帧
- 节奏：她来问就说（不排段、不预取）
- 记忆：`video_segments.json`（当次有效）
- 退化：无字幕 → OCR → 帧拼图

### 11.5 anime（番剧）

- 触发：激活条件满足，URL 含 `/bangumi/play/ep…`
- 素材：**字幕条 OCR**（进片定位一次，之后只认那一小条）+ 滚动摘要 + 集号/集标题（PGC 反查）
  + **带时间轴的弹幕窗口**（当前播放位置 ±30 秒内，去重、过滤剧透词；
    **不用热评**——热评多由看完的人写，天然带剧透）
- 节奏：她来问就说
- 记忆：`anime_progress.json`（哪部、第几话、看到第几分钟）
- 集末：进度 ≥95% 或切下一集 → 读这一集简介做**回顾**（已看完，不算剧透）
- 退化：OCR 读不到 → 帧拼图

### 11.6 live（直播）

- 触发：激活条件满足，URL 含 `/live/`
- 素材：**连续转写**（10 秒一段，环形缓冲常备）+ **高频弹幕 top 5** + 当前帧
- 弹幕：只当可选素材，提示词写死「不要复述弹幕、不要汇报热度」
- 节奏：她来问就说
- 记忆：滚动转写 + 每 5 分钟增量摘要
- 退化：转写挂 → 只看画面 + 弹幕

### 11.7 course（网课）

- 触发：会议软件前台，或浏览器课堂页
- 素材：连续转写 + **翻页才给的帧对比**（见 11.10）
- 节奏：她来问就说；画面静止 + 无转写 → 不出声
- 记忆：按「这节课」建会话，课后可结算一段笔记
- 退化：转写挂 → 只看 PPT

### 11.8 成本对照

| 场景 | 不做门槛 | 做门槛 |
|---|---|---|
| 刷 3 分钟视频切走 | 抓字幕 10s + OCR 定位 2s + 1~2 轮 | 按 normal，零准备 |
| 看 24 分钟番 | 一次性准备 | 一样（一次性） |
| 直播停 5 分钟 | 全程转写 | 只最后 3 分钟进 live |

### 11.9 实现顺序

1. `/player` + 会话状态 + **停留计时**（不含模式行为，先只记录，验证门槛准不准）
2. normal 不变；video 先接「yt-dlp 字幕 + 前 90 秒窗口」
3. anime 接「字幕条 OCR + 定位」
4. live/course 接「环形缓冲 + 连续转写」
5. 最后接滚动摘要与集末回顾

### 11.10 帧拼图为什么只给网课用

帧拼图（多帧拼一张）解决的是「**画面长时间不动、偶尔变一下**」的场景——网课翻 PPT、看文档。

- **视频/番剧不需要**：画面一直在动，单张当前帧就够；拼图反而让每格变小、字变糊，还多花 token。
- **网课需要**：一页 PPT 停三分钟，单帧看不出"翻页了"，拼起来才看得出「刚才那页 → 这页」。

实现：复用现有帧缓冲的 dHash（本来就在算变化分）。
`course` 档只保留「最后一次变化前一张 + 变化后一张」，翻页时给两格对比；
没翻页就不拼，只给当前帧。所以它**不是定时拼**，是**事件拼**。

### 11.11 能不能调用她自己的「主动识屏」

**有快捷键，但程序按不动。** 实测结论：

1. 桌宠配置里确实有三个全局快捷键：
   `hotkey_open_chat`（开聊天）、`hotkey_look_screen`（**看看屏幕**）、`hotkey_screen_capture`（截图）。
   把 `hotkey_look_screen` 设成 `ctrl+alt+k` 后，她的日志写：
   `全局快捷键已生效：看看屏幕=Ctrl+Alt+K`，说明注册成功。
2. 但**我们用 SendInput 注入这个组合键，她没反应**（识屏计数不动、日志没有事件）。
3. 做了完整对照实验（都在这台机器上跑）：

   | 注入方式 | SendInput 返回 | 收到 WM_HOTKEY |
   |---|---|---|
   | 只给 wVk | 1（成功） | 否 |
   | 只给扫描码（KEYEVENTF_SCANCODE） | 1 | 否 |
   | wVk + 扫描码 都给 | 1 | 否 |
   | 单键 F9（无组合） | 1 | 否 |

   而且 `GetLastInputInfo` 在注入后确实更新了——**说明按键进到了系统**，
   只是**全局热键的激活被过滤掉了**。
   为了排除沙箱因素，又用**计划任务**（脱离 DSH 沙箱的用户会话）跑了同一段探针，
   结果一模一样：输入被接受，热键不触发。

   **但真正的原因不是「系统不让」，而是「我们的进程在沙箱里」。**

   后来用一个 tkinter 窗口做对照：在 DSH 进程里注入 → 窗口一个按键都收不到；
   **改用计划任务（沙箱外的普通进程）跑同一段注入 → 窗口收到了按键**。
   也就是说：沙箱内的进程 SendInput 会被系统静默丢弃（返回成功但没人收到），
   沙箱外正常。

   于是做了一个「按键助手」`D:\app1\paopao_pet_gateway\key_helper.py`：
   监听 `127.0.0.1:9893`，收到一行 `look` 就把桌宠窗口顶到前台再按 `ctrl+alt+k`，
   收到 `ctrl+alt+k` 就直接按。启动项：`%APPDATA%\\Microsoft\\Windows\\Start Menu\\Programs\\Startup\\泡泡按键助手.vbs`
   （登录时用 pythonw 静默拉起，和 DSH 沙箱无关）。

   实测：**第一次按成功**——识屏计数 27→28，她的日志出现 `sync_look_to_chat`（就是那个已知 bug）；
   **之后连续按多次都不再触发**，怀疑是她那边有冷却或状态条件（`min_request_interval_seconds=60`
   之类），这次没来得及查清。

   所以结论要分两层说：

   - **能按**：沙箱外的助手确实能让她的快捷键生效（至少第一次验证通过）。
   - **还不稳**：重复触发为什么被吞，还没搞明白。别把它当主路径。

所以：

- **快捷键是给人按的**：你按 `Ctrl+Alt+K` 她就会看一眼屏幕。
- **程序按不动**：想「由我们让她看一眼」，只能自己实现。

自己实现反而更可控：网关本来就有帧缓冲、provider、TTS，加一个 `/look` 接口——
截一张、按模式拼上下文（看番时自动带上前 90 秒台词）、调模型、说出来。
人设和声音照用，只是这次是我们驱动的。

### 11.12 「让她看一眼」的链路（2026-11-15 晚定稿：热键优先，菜单兜底）

**热键是能用的。** 21:53 复测：先左键点她再注 `Ctrl+Alt+K` → vision 1→2；
什么都不做直接注 → 2→3。两次都成。

之前判「注入触发不了热键」是**下结论太早**：那时的失败更可能是那只实例/助手进程的临时状态
（换一个实例、重启助手后就好了），不是原理上不行。**结论改成：热键优先。**

所以正式链路是：

```
中键点她（或 POST /look）→ 助手注一次 Ctrl+Alt+K → 她的识屏请求到网关（带 4 帧拼图）
```

**菜单版只当兜底**（`menulook`）：热键 8 秒没反应才试，而且只在 `/look` 里试——
`look_guard` 保底看屏不会弹菜单，避免打断看片。

菜单兜底的做法（保留记录）：

```
现读 pet-runtime-v2-<pid>-slot-0.json 拿到她当前位置
  → 在宠物中心右键（她的菜单真的会弹出来）
  → 菜单是带焦点的普通窗口：Down ×3 → Enter 选中「看看屏幕」
  → 她的识屏请求到达网关（带 4 帧拼图）
```

实测：`POST /look` 返回 `{"ok": true, "vision_before": 1, "vision_after": 2, "via": "hotkey"}`。

实现位置：

- `key_helper.py` 的 `do_look()`：读实时坐标 → 右键 → Down×3 → Enter（helper 必须在沙箱外）；
- 网关 `press_look()` → helper 的 `look` 命令；
- `POST /look` 等识屏计数涨了才算成功；
- `look_guard`（保底看屏）走的是同一条。

**中键手势**（`mouse_look`）：网关 40ms 轮询真实鼠标中键（钩子在这台机器收不到事件，
轮询可以），光标落在宠物矩形内就替她走上面那条链路。她本身没有中键动作——这是外挂的。

注意两点：
1. 坐标必须现读，她会走动；缓存的一定点偏（会点到浏览器上，弹出 Edge 的右键菜单）。
2. 菜单项顺序随版本可能变，`Down ×3` 是按当前版本数出来的；升级后要重数。

## 14. 通用视频模式（2026-11-16 加）

B 站那两条（video / anime）靠字幕和页面信息，**别的视频拿不到这些**。这一节是「不是 B 站 的视频」
也能一起看的兜底：前台播放器 + 音频环回 + 键鼠低活跃 → 自动判定，素材先听声音、听不出来再读字幕条。

### 14.1 怎么判「他在看视频」

三个信号，**不要求键鼠完全不动**（看片时会拖进度、调音量）：

| 信号 | 判据 |
|---|---|
| 前台是浏览器/播放器 | 进程名在 `video_watch.players` 里（chrome/msedge/firefox/vlc/potplayer/mpv/bilibili…） |
| 环回有声音 | 最近 3 秒的 RMS 峰值 > `audio_threshold`（默认 0.004） |
| 键鼠低活跃 | 空闲 ≥ `input_idle_seconds`（60 秒）**或** 最近 3 分钟输入 ≤ 15 次 |

**进入**：三个都满足，且同一窗口连续 ≥ `enter_min_seconds`（90 秒）——短切片不会误触发。
**模式细分**：按 URL/标题自动进 `anime`（番剧）/ `live`（直播）/ `video`（普通视频）；
已经在视频类模式里换内容时，`switch_seconds`（20 秒）内跟着切，不会一直停在 video。
**退出**（照 11.2 的宽容版）：

| 情况 | 宽限 |
|---|---|
| 前台切走但片子还在放 | 5 分钟（只记账，不主动说话） |
| 停在播放器上没声了 | 10 分钟（可能去倒水） |
| 停了又切走 | 2 分钟 |

退出时只把 `video` 切回 `auto`，而且**只在 `mode_source=auto-video` 时**才动——手动设过的模式一概不碰。

### 14.2 素材：先听，再读

1. **音频环回**（WASAPI loopback，`soundcard`）：10 秒一包 → 9881 转写 → 滚动保留最近 12 条；
2. **转不出来就退 OCR**：连续 3 段转写的中文字符占比 < 25%（外文片/纯音乐/噪音），
   自动切「字幕条 OCR」——只截**下三分之一**，每 2 秒一次，扫到相同文本不重复记；
3. B 站 以后接字幕 OCR 时**用同一个 `ocr_worker.py`**（常驻 rapidocr 小工，模型只加载一次，
   一次调用约百毫秒级，不用每次起进程）。

喂给模型的不是全文，是「窗口 + 最近 12 条对白/字幕 + 当前帧」，并写死：不复述、不剧透、不报进度。

### 14.3 「哦，看视频啊」怎么来的

**不再注入「第一次开口」引导（2026-11-17 去除）**：切模式时已经有气泡 + 语音提示，
再往下一轮对话里塞「刚进入看视频模式，第一次开口带一句」就重复了。现在只保留
当前模式/剧情/播放进度的常驻上下文，不再有一次性提示词。

### 14.4 配置（`config.json` → `video_watch`）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关 |
| `poll_seconds` | 2.0 | 判定间隔 |
| `enter_min_seconds` | 90 | 同一窗口连续多久才进 |
| `switch_seconds` | 20 | 已经在视频类模式里换内容（普通视频↔番剧↔直播）的确认时间 |
| `game_takeover_seconds` | 90 | 从游戏模式退出来、前台换成播放器有声后，按进入判断同样稳 90 秒再接管成视频/直播 |
| `audio_threshold` | 0.004 | 环回 RMS 门限，太吵就试 0.008 |
| `input_idle_seconds` | 60 | 键鼠空闲多久算「低活跃」 |
| `input_events_window` / `input_events_max` | 180 / 15 | 窗口内输入次数上限（空闲不够时的备选判据） |
| `away_grace_seconds` | 300 | 前台切走但还在放 |
| `paused_grace_seconds` | 600 | 停在播放器上没声 |
| `paused_away_grace_seconds` | 120 | 停了又切走 |
| `asr_chunk_seconds` | 10 | 转写一段多长 |
| `asr_min_cjk_ratio` | 0.25 | 低于它认为「不是中文」，连续 3 段就转 OCR |
| `ocr_interval_seconds` | 2.0 | 字幕条多久扫一次 |
| `ocr_bottom_ratio` | 0.34 | 只扫下三分之一 |

依赖：`soundcard`（已装进网关那个 Python）；OCR 用 `D:\app1\tools\ocrvenv`。

### 14.5 验证

```powershell
(Invoke-WebRequest http://127.0.0.1:9888/status -UseBasicParsing).Content   # 看 "video": {...}
(Invoke-WebRequest http://127.0.0.1:9888/doctor -UseBasicParsing).Content   # 看 video_watch
```

正常时：没人看片 → `"state": "idle"`；在看 → `"state": "active"` 并且 `lines` 往上涨；
`audio` 是环回有没有声。故意看一个外文片，日志里会出现
`视频模式：转写不像中文（x%），改读字幕条`。

**坑**：换耳机/蓝牙会断环回（自己 2 秒重开，日志有 `环回录音断了`）；没有 `soundcard` 时
`audio` 永远是 false，就进不了模式（这时只靠窗口+键鼠，宁可不进）。

## 15. 头顶气泡：让我们生成的话也用她那套气泡显示（2026-11-16 加）

桌宠的**原生气泡**没有对外入口（事件通道只能写状态，`/api/respond` 早在 2026-10 删了）。
所以这里换了条路：**把她的气泡代码原样搬出来，在我们自己的进程里画**——长得一模一样，
不用改桌宠、不用重新打包。

### 15.1 怎么拼起来的

```
网关（9888）──stdin JSON 行──> bubble_host.py（Qt 进程）──> 屏幕上的气泡
      POST /bubble                    │
                                       └─ 每次弹之前读她的 config.json
```

- `D:\app1\paopao_pet_gateway\bubble\`：从上游搬来的 `speech_bubble.py`（MIT）、
  `speech_bubble_text.py`，**只改了 import**，以后好跟上游对照升级；
- `bubble_host.py`：Qt 小工。读 stdin、画气泡、跟着她走；
- `bubble_bridge.py`：网关这边的桥。按需拉起小工，发指令，进程死了下次重拉；
- 为什么不让网关自己画：Qt 事件循环和语音网关不是一个东西，**Qt 崩了不能把语音一起带走**。

### 15.2 怎么用

```powershell
# 让她头顶出气泡（3.2 秒后自己消失）
$body = @{ text = "这是网关让她说的话" } | ConvertTo-Json -Compress
Invoke-WebRequest http://127.0.0.1:9888/bubble -Method POST -Body $body `
  -ContentType 'application/json; charset=utf-8' -UseBasicParsing
# 也可以指定时长（毫秒）
@{ text = "多看一会儿"; duration_ms = 8000 } | ConvertTo-Json -Compress | ...
```

单独试气泡（不经过网关，随手看一眼位置对不对）：

```powershell
& "C:\Users\zuo'yu\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe" `
  D:\app1\paopao_pet_gateway\bubble_host.py --demo "测试一下气泡"
```

`config.json → bubble`：`enabled`（总开关）、`duration_ms`（默认 3200）、
`max_chars`（默认 60，超了截断）。

### 15.3 跟她的设置同步（每次都读）

**每次弹之前读一次** `%APPDATA%\dsh-pet-standalone-webm-chat\config.json`，
不轮询、不缓存，所以她在设置里改完，下一句就是新样子：

| 她的键 | 用途 |
|---|---|
| `self_talk_bubble_style` | 五种样式：`classic_top` / `paper_left` / `glass_right` / `soft_blue_top` / `breath_bubble` |
| `bubble_text_scale` | 50～300，100=默认；**气泡和字号一起放大** |
| `self_talk_duration_seconds` | 气泡停留时长（默认 3.2 秒） |

读坏了（文件正在写、JSON 半截）**沿用上一次的值**，不退回默认——不然气泡会突然变样。
她那些键没写进 config.json 时就是默认值（100 / classic_top / 3.2）。

> 不透明度不用同步：`pet_opacity` 管的是整只桌宠，气泡是独立窗口，不跟着它变。

### 15.4 位置、四档缩放、边角落（借用 `window.py` 的规矩）

- 位置：读 `%APPDATA%\...\pet-runtime-v2-<pid>-slot-0.json` 里的 `x/y/w/h`（她**每次移动都会
  重写**）——**注意：这个文件其实是"定期存档"，实测只有 1Hz**，所以她走着的时候我们最多
  落后约一秒、看着就是"气泡显示在她上一秒的位置"。现在拿最近两次样本估速度往前推
  （最多 0.6 秒 / 200px）把这段补上；想要真正的实时，只能让她自己高频写位置（要改桌宠本体，不建议）；
- 缩放：读 `config-slot-*.json` 的 `scale`（四档那个），传给 `show_text(..., pet_scale=)`；
- **不额外加偏移**（2026-11-16 踩过的坑）：曾经做过「参照她的气泡 + 学偏移」，结果
  偏移每次弹之前加到锚点上、跟随又把偏移后的位置当新锚点，越按越偏。现在一律照她
  原本的逻辑：锚点=精灵包围盒，`show_text(text, anchor, pet_scale=)`，跟随用
  `reposition`/`reflow`，不做任何二次挪位；
- 跟随：每 30ms 对一次。**位置变了用 `reposition`、缩放变了用 `reflow`**——照她自己的做法
  （`window.py` 里也是这么分的），别每拍都 reflow，那样字会跟着抖；
- **边角落**：不用我们算，气泡组件里 `bubble_rect_for_anchor()` 本来就会挑位置——
  依次试「正上方 → 左上/右上 → 右侧 → 左侧 → 下方」，要求**整块落在屏幕可用区里**
  （`screenAt(锚点中心).availableGeometry()`，自动避开任务栏、认多屏），并且**不压住她**；
  都不行就把最近的候选**夹回屏幕内**、选压住她面积最小的那个。实测四角：

  | 锚点（逻辑坐标） | 气泡落点 | 结果 |
  |---|---|---|
  | 左上 (10,10) | (177,83) | 放到她右边，没出屏 |
  | 右上 (1878,10) | (1744,83) | 放到她左边 |
  | 左下 (10,894) | (26,835) | 放到她上方 |
  | 右下 (1878,894) | (1894,835) | 放到她上方，贴着屏幕右缘但没切掉 |

- **看不见就不弹**（抄她 `show_bubble` 第一行 `if not self.isVisible(): return False`）：
  气泡小工先看那个 pid 有没有一块像样的可见窗口，再看锚点是不是缩成了边栏
  （宽或高 < 80px）——她收进托盘 / 缩边栏时直接跳过，并回 `shown=false + reason`。

### 15.5 验证

```powershell
(Invoke-WebRequest http://127.0.0.1:9888/status -UseBasicParsing).Content   # "bubble": {"alive": true, "shown": N}
(Invoke-WebRequest http://127.0.0.1:9888/doctor -UseBasicParsing).Content   # "气泡小工 在跑（已弹 N 次）"
```

`POST /bubble` 的返回是**真的回执**，不是“发出去就算成功”：

```json
{"ok": true, "shown": true, "reason": "", "text": "借了它的定位逻辑",
 "anchor": [1578, 809], "screen": [1588, 750],
 "status": {"alive": true, "shown": 1}}
```

`anchor` 是她精灵的位置，`screen` 是气泡实际落地位置；`shown=false` 时 `reason` 会是
`pet-hidden` / `pet-docked` / `no-pet` / `no-ack`。

实测：`/bubble` 一打，她头顶就出原生气泡（奶油色圆角 + 小尖），3.2 秒后自己消失；
日志 `logs\bubble.log` 里能看到 `弹：...（样式 classic_top，字号 1.00，缩放 0.72，3200ms，气泡 上屏）`。

**坑**：气泡小工是**按需拉起**的，第一次弹会慢半秒（Qt 启动）；网关重启后它也会跟着重启
（stdin EOF 自己退）。小工挂了只会没气泡，语音不受影响。

## 16. 语音模式（2026-11-16 加）

按一下热键开录，停顿够久自动结束，转写 → 模型 → **她开口 + 头顶气泡**。

### 16.1 一次对话的样子

| 阶段 | 头顶气泡 | 说明 |
|---|---|---|
| 按住说 | 「我在听」 | **只是提示，不出声**；一直在，直到结束或取消 |
| 说完了 | 「唔……我想想」 | 转写 + 模型这段 |
| 开口回答 | 回答正文 | 跟 TTS 一起出；停留按字数算，3.2～5 秒 |
| 没听清 | 「没听清，再说一遍？」 | 转写为空 |
| 出岔子 | 「我这会儿有点卡壳…」 | 模型/合成失败 |

**没有提示音**（看视频时很吵），状态全靠气泡。

托盘里选「语音关」= **热键也跟着关掉**：按 `Ctrl+Alt+V` 不会开录，只在头顶冒一句「语音关着呢」。

### 16.2 参数（都是会话里定死的）

| 项 | 值 | 说明 |
|---|---|---|
| 热键 | `Ctrl+Alt+V` | 按一下开录，再按一下取消；**系统级注册**（游戏里也认），见 16.9 |
| 静音断句 | 1.2 秒 | 你说完停顿这么久就算说完 |
| 最长 | 30 秒 | 到点强制结束 |
| 最短 | 0.3 秒 | 更短的当咳嗽丢掉 |
| 没人说话 | 3 秒收工 | 免得干等 30 秒 |
| 电话模式听音窗 | 8 秒 | `mode=call` 时她说完自动再开一个窗口 |

### 16.3 链路

```
麦克风 16k 单声道 → 能量 VAD 断句 → 9881 /v1/audio/transcriptions
   → 模型（桌宠人设 + 「语音模式」提示：短句、口语、不分点）
   → 现有 TTS 流水线（第一小句流式）
   → 头顶气泡（和 TTS 一起出）
```

**要不要看屏**：默认不看——语音对话多数是在问你事，每次强制截屏多 2～5 秒。
只有话里带「这个 / 看看 / 看一眼 / 屏幕 / 我这样」这类词，或者当前在视频模式，
才顺手带一张当前帧。

**半双工**：她说话的时候**不听**（没有回声消除，听自己的声音会自激）。
`call` 模式是她说完自动开听音窗；真正的“她说着我插话”要耳机 + 回声消除，`barge_in`
现在是 false，别急着开。

### 16.4 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/voice` | 状态（mode/state/turns/热键） |
| POST | `/voice` | `{"action":"start"}` 开录 / `{"action":"stop"}` 取消 |
| POST | `/voice/input` | `{"text":"..."}` **键盘兜底**：当成“听清了”直接回答（没麦时也能测） |

```powershell

$b = @{ text = "老大，听得到吗？" } | ConvertTo-Json -Compress
```

### 16.5 麦克风怎么挑（这节很重要）

网关启动时**逐个试设备**（0.35 秒看有没有数据），跳过「立体声混音 / 线路输入」，
优先名字像「麦克风 / mic / 耳机 / headset」的。日志里会打：

```
试设备 #10 麦克风 (Realtek HD Audio Mic input) → 0 采样
试设备 #15 耳机 (... iKF-King Pro⁺) → 0 采样
麦克风：麦克风 (Realtek HD Audio Mic input)（#10）
```

**0 采样 = 这个设备根本不出数据**（插孔没插麦、设备被别的程序独占、蓝牙耳机没切到
通话/HFP 模式）。想指定设备就写 `config.json → voice.device`：填序号（`15`）
或名字片段（`耳机`）。

### 16.6 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关 |
| `mode` | `ptt` | `off` / `ptt`（按键）/ `call`（电话：说完自动再听） |
| `hotkey` | `ctrl+alt+v` | 目前只认这个组合 |
| `vad_silence` | 1.2 | 静音断句（秒） |
| `max_record` / `min_record` | 30 / 0.3 | 秒 |
| `energy_threshold` | 0.012 | 多大算“有人在说”；安静环境可降到 0.008 |
| `no_speech_timeout` | 3.0 | 没人说话多久收工 |
| `call_window` | 8 | 电话模式的听音窗 |
| `device` | "" | 空=自动；可填序号或名字片段 |
| `barge_in` | false | 打断（要耳机 + AEC，先别开） |

### 16.7 已知限制

- **没有麦克风就录不到**：2026-11-16 安装时实测这台机器三块输入设备都是 0 采样、
  蓝牙耳机干脆打不开（`Unanticipated host error`，多半被占用了）。插上麦/把耳机切到
  通话模式后重启网关即可。

- 声音全走 16k 单声道给 ASR；设备不吃 16k 时自动按它默认采样率录、再线性降到 16k。

## 17. 托盘菜单：模式切换（2026-11-16 加）

托盘图标住在**气泡小工**里（同一个 Qt 进程），网关一启动就把它拉起来——不用等第一次弹气泡。图标就用桌宠那只的头像（`assets\paopao.png`，跟插件 logo 同一张）。

### 17.1 菜单长什么样

```
当前：自动模式 · 按键说话 · 锁5分钟          ← 不可点，只是状态
──────────────
○ 关闭
○ 自动模式
○ B站视频
○ B站看番
○ 玩游戏
○ 通用视频
──────────────
手动锁 ▸ 5 分钟（默认） / 一直保持
──────────────
○ 语音关
○ 按键说话
○ 语音电话
```

模式是**单选**（`QActionGroup`），手动锁是另一个**单选**子菜单，语音也是单选。
默认勾「自动模式」+「锁5分钟」+「按键说话」。

> 2026-11-17 说明：菜单上的「自动模式」既是通用模式、也是自动判定的入口。
> **5 分钟档不锁自动模式**（否则自动切换会被卡 5 分钟）；「一直保持」档才把它也锁住。

**「关闭」= 不自动进看视频/看番**（跟桌宠自己的「主动识屏」开关一个意思）：正在看会立刻退出
（日志 `通用视频模式：退出（模式关闭）`），之后也不进；而且它**不会被 10 分钟规则改回自动**
——你明确说了不看，就一直不看，直到你重新点「自动模式」或某个具体模式。

> 2026-11-16 修：以前「关闭」还把**识屏播报一起静音**了（`speak_this=False`），
> 结果她照常识屏却一句不出声，看着像语音坏了。现在「关闭」只管“别自动进看视频”，
> 识屏照常出声；真要静音（夜里/开会）开 `mute_vision_when_off=true`。

**左键单击托盘图标 = 开关语音电话**（最常用的动作不用点两层菜单）。

### 17.2 行为

- **只有用户点才冒气泡**：默认 3.2 秒，说一句就完（「哦，看番去啦。」「行，不看了」
  「语音关掉了」）；自动切换、启动都不冒，免得吵；
- **手动选的模式按「手动锁」走**：`source` 记成 `tray`；默认锁 5 分钟，到点只放开
  （source 变 `tray-released`，模式不变，日志 `模式锁到期…交回自动判定`）；
  手动锁切「一直保持」就不放开，除非再勾别的模式或改回 5 分钟；
- 选 **通用视频** 会顺手调 `VideoWatcher.force()`，不用等 90 秒的自动判定，立刻进；
- 勾选状态每秒从 `/status` 拉一次同步（`blockSignals` 挡住，不会自己触发自己的点击），
  所以从别处改的模式，托盘勾也会跟上；
- 当前这一格是哪项，看 `(mode, mode_source)`：`off` → 关闭，`video` + `auto-video/tray-generic`
  → 通用视频，`video` + 其它 → B站视频，`anime` → B站看番，其它 → 自动模式。

### 17.3 接口（托盘点一下就是打这些）

```powershell
# 观看：自动 / B站视频 / B站看番
Invoke-WebRequest http://127.0.0.1:9888/mode -Method POST -Body '{"mode":"anime","source":"tray"}' -ContentType 'application/json'
# 通用视频（会立刻 force）
Invoke-WebRequest http://127.0.0.1:9888/mode -Method POST -Body '{"mode":"video","source":"tray-generic"}' -ContentType 'application/json'
# 语音：off / ptt / call
Invoke-WebRequest http://127.0.0.1:9888/voice -Method POST -Body '{"action":"set_mode","mode":"call"}' -ContentType 'application/json'
```

**实测**（2026-11-16）：点「看番」→ 气泡「哦，看番去啦。」、`/status` 里 `mode=anime`；
点「通用视频」→ `video.state=active`（当时前台是原神）；点「语音关」→ `voice.mode=off`。

> 切换模式**没做**全局热键，也没做 QQ 命令——用不上，一条托盘就够。
> 语音开录那个 `Ctrl+Alt+V` 仍然在（它只开录，不切模式）。
## 18. 固定句子预合成（2026-11-16 修了个真 bug）

以前 `warm_phrases()` 写缓存用的键是 `md5(文本|语速|音量)`，而播的时候 `_voice_key()`
用的是 `md5(后端身份|文本|语速|音量)` —— **两个键对不上，预热出来的文件永远命中不了**，
等于每次都现合成。所以 DSH 状态、提示音这些固定句子一直在“每次现生成”，质量还不稳定。

修完（2026-11-16）：

- 预热统一走 `_voice_key()`，跟播放查找是同一条路；
- 预热范围扩到「DSH 状态模板 + 语音模式那几句（唔……我想想 / 没听清 / 卡壳 / 语音关着呢）
  + 托盘反馈（哦，回自动了 …）」，见 `phrases.py`；
- 想重生成某句（比如听着不好）就 force 一次：

```powershell
# 只重生成指定几句，并把缺的都补上
$b = @{ phrases = @("收工，本鲸鱼娘要吃口白饭。"); force = $true; all = $true } | ConvertTo-Json -Compress
Invoke-WebRequest http://127.0.0.1:9888/warm -Method POST -Body $b -ContentType 'application/json; charset=utf-8'
# 只补缺的（不重生成）
Invoke-WebRequest http://127.0.0.1:9888/warm -Method POST -Body '{"all":true}' -ContentType 'application/json'
```

缓存文件在 `audio\phrases\<key>.wav`；日志 `短语缓存预热完成：新增 N 条`。
`force` 会先删再合成，所以真换了音色/语速这类的，记得加 `force`。
### 16.9 热键为什么在游戏里不灵（2026-11-16 修）

一开始是用 `GetAsyncKeyState` 每 50ms 轮询「Ctrl+Alt 是不是按着」。桌面里好用，
**到了游戏里就瞎了**——原神那种前台窗口的完整性级别比我们高，Windows 规定低完整性
进程在这种时候读不到 `GetAsyncKeyState`，所以永远返回 0。

改成 `RegisterHotKey(NULL, id, MOD_ALT|MOD_CONTROL|MOD_NOREPEAT, V)` + 单独一个线程跑
`GetMessage`，收 `WM_HOTKEY`。这是系统级注册，**游戏前台也照收**，跟截图工具一个路子。

- 注册失败（组合被别的程序占了）会在日志里写清楚，并**退回轮询**（桌面能用，游戏不行）；
- 状态看 `GET /voice` 的 `hotkey_ok: true`；
- 已经注册成功时轮询会自动让位，不会一次按键触发两次。
### 17.4 跟桌宠「主动识屏」开关联动（2026-11-16 加）

**一个开关管两头**：桌宠设置里那个「主动识屏」，就是我们的总开关。

| 桌宠「主动识屏」 | 我们 |
|---|---|
| 打开 | 进「自动模式」，**出声**说「主动识屏已开启，我会偶尔看看你正在用的软件。」（**不冒泡**：桌宠那边自己会弹「主动识屏已开启~…」） |
| 关闭 | 进「关闭」，**冒泡 + 出声**「行，不看了」（桌宠那边关掉时不弹泡，这句得我们补上）；正在看的会立刻退出 |

托盘里点「关闭」也一样：气泡小工弹「行，不看了」，网关这边补一声。
两句都在预合成清单里（`phrases.ALL`），开口零延迟。

反过来，托盘里点 **B站视频 / B站看番 / 通用视频 / 自动模式**，会顺手把她那边的
「主动识屏」也打开；点 **关闭** 就一起关掉。实现是直接改 `config.json` 的
`proactive_screen.enabled`（先写临时文件再 `os.replace`，她有 `QFileSystemWatcher`
会热重载，不会读到半截）。

**防打架**：我们自己写配置那一下会在 `_proactive_self` 记一笔，6 秒内那个变化不触发
「开关变化 → 改模式」的逻辑——不然刚点「B站看番」会被开关回调立刻改成「自动」。

实测（2026-11-16）：
- 把 `enabled` 改 true → 1.5 秒内 `mode=auto`、日志 `桌宠打开主动识屏 → 自动模式`；
- 改 false → `mode=off`、日志 `桌宠关掉主动识屏 → 关闭`，同时 `通用视频模式：退出（模式关闭）`；
- 托盘点「B站看番」→ `config.json` 里 `proactive_screen.enabled` 变成 true，模式仍是 anime。
